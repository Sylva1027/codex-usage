## 2. 小卡与监工规则

每卡目标 **15–20 分钟，包含实现、1–3 项核心验证与报告**。一次只派一张；已通过的直接前置立即释放后继，不把整个 B 包绑成一次任务。

到约 15 分钟仍有阻碍，worker 交当前 diff、实际失败、剩余行为；预计超过 20 分钟则主审拆出有明确输入/输出的后继。不能靠少测钱数、放宽断言或吞错误压时，也不让“顺便把所有调用改完”成为长尾。等待锁/另一卡时换无依赖卡，不伪报并行度。

报告只需：卡号、改动文件、实现行为、命令/结果、未完成项。主审阅读 diff 和关联调用，独立复跑必要验证，再给“接受 / 需修正 / 等依赖”结论。一次验收记录即可，不建通用工作流系统。

不新增运行依赖、插件系统、通用价格引擎或配置框架；复用既有 overlay/differences、原子写入、resolver、费率/峰谷校验、刷新 promise、可控时钟和测试库。只操作临时测试配置/数据库，不改真实价目、索引、账本或正式服务。

## 3. 冻结接口与实现取舍

### 3.1 页面与 API 只认 A §3

D03 已增加独立 `editVersion`：实时 GET/成功 PUT 返回，A 在打开草稿时保存并回传；存在该字段时只校验编辑版本，不允许费用 `version` 兜底绕过。旧 version-only/无版本格式兼容；费用版本不混入手动锁状态。快照不提供实时编辑版本。

A 联调补齐 `manualOnlyEntries` 与两个明确 capability，详见 A §3.2。D07 接通后启用 `routeEditing`，D11 接通后启用 `rowRefresh`；此前带 model 的刷新请求明确拒绝，不静默转全局。这是现有功能的真实接通状态，不新增一套发现或 CRUD 服务。

[A §3](2026-10-24-pricing-implementation-A.md#3-ab-共用的页面api-契约)是页面字段与 PUT/refresh 行为的唯一施工契约；K、D 开卡前均需读。主要接缝为：

- 原有 costEstimate 字段继续使用；`priceMode` 区分第一批 minimum-fallback-scenario 与第二批 priced-only-scenario。
- GET 返回有效 models/routes、稀疏 manualOverrides、独立价格/FX 状态；PUT 仍传有效目录，restoreFields 表达显式撤销。
- 原 resolver 两参数调用兼容，第三参数为 routes；线路命中用 matchType=route。
- 行级 refresh 使用完整 model、force:false；全局 force:true 保留。

内部函数不为满足计划名称而另套包装；确需改变已约定导出签名时，由主审同步调用者与契约，不让 worker 各自发明变体。

### 3.2 有效目录与持久化

有效目录增加 `routes: {}`。模型名仍按现有规则、最多 256；线路键允许 /，总长 1–160、最多 512。明确规范化后再判空段、大小写碰撞、危险对象键；归一化冲突不能后写覆盖前写。canonical 是非空合法模型标识，允许尚无独立模型价的 canonical，但不能据此借价。

手动文件 schema 3 示例：

```json
{
  "schemaVersion": 3,
  "checkedAt": "2026-10-24",
  "modelOverrides": {},
  "routeOverrides": {
    "seller-a/example-model": {
      "canonical": "example-model",
      "currency": "USD",
      "short": { "input": 1, "cachedInput": 0.1, "cacheWrite": 1.2, "output": 3 },
      "long": { "input": 1, "cachedInput": 0.1, "cacheWrite": 1.2, "output": 3 }
    }
  }
}
```

价格是合成夹具。手动文件保存的是稀疏覆盖，**不是有效 routes 全量镜像**；新手动条目无自动底值时自然保存完整条目。自动缓存单独存最新有效自动 models/routes 及证据，手动值不能污染它。

读取兼容 schema 2、旧全量价目、旧自动缓存和无 routes 的配置；未知 schema/非法新增字段报错并保留原文件，不假装成功或退成空目录。第一批仍可写 schema 2；D05/D06 才升级手动文件。schema 迁移只在保存时原子写入，不因只读加载重写用户文件。

PUT 全目录保存须比较**同版本当前有效值与提交值**，只对实际编辑的字段合并手动补丁，并保留未动的已有覆盖。不能每次简单 differences(最新自动层, 整份有效目录)，否则会意外删除恰好等于自动值的手动锁定。restoreFields 优先作为明确操作验证；path 使用允许字段集合，拒绝危险路径、重复/冲突操作；重组后再验证完整有效目录。无底值导致必需字段缺损则整次拒绝，不补 0。

保留并发版本检查与原子写入/失败回滚；并发 PUT 的版本判定、构造补丁和发布不能都在同一旧版本上成功。复用现有方式，必要时在保存入口做最小串行化，且自动刷新提交不能丢失同时保存的手动字段。自动层被覆盖的字段继续缓存更新，撤销时取最新有效值。

### 3.3 费率、身份与版本

- **新条目严格、旧数据兼容。** 新增普通模型/线路必须有经确认的完整必需费率与适用上下文政策。长短档同价由编辑器明确复制后提交两档；分档必须有阈值。不把旧 validator 的缺 long 自动复制用于新候选；旧内置及旧文件的已支持兼容迁移不顺便推翻。
- **K01 已冻结接缝。** `validatePricingCatalog(value, { strictNewModels })` 由保存/API 根据当前目录识别新增键后调用，必须在旧归一化补 long 之前检查原始提交；旧加载无选项调用不变。新条目无 Fast 时只生成 `allowFastFallback:false`，不生成 fast 字段覆盖；明确 Fast 对象存在时可直接生效。D 保留该推导策略字段，不展开成 `fast:null`。新标准或 Fast 两档任一组不同都须显式阈值。
- 新来源缺写入/长档政策不能发布完整候选；Fast 未证实不 ×2，峰谷不继承。没有适用 Fast 费率时首版新线路/新模型保持该场景未定价，不另做标准场景选择 UI。已有明确的厂商/产品政策和 Claude 情景解释继续保留。
- 首版线路仅取原始 model 中已完整、可靠的显式线路键；不引入裸名请求关联、不用 perf provider/当前配置补卖家。已有 anthropic 等产品别名保留原有模型语义，不重解释成已核实卖家。
- 精确且适用的线路先于模型价，明确免费规则保持原优先级。canonical 不复制政策；未知线路不剥前缀匹配裸名。已有可靠模型价情景仍能显示，但不能声称线路确认或账单验证。
- 第二批只取消**无可用费率时的全局最低价补入**；模型内缺 token 明细的现有假设按原原因继续统计。全未定价金额为 null，免费为 0；部分已知按已定价部分合计，不把 unknown 当 0 单价。
- 有效费用版本包含 rates、FX、场景政策及 routes/canonical 等影响输出的绑定。仅错误/重试/核验日期变化不导致费用重算；编辑并发版本与 statusVersion 可以有各自目的，不强行共用一种哈希。catalog 的对象身份更换保持 WeakMap resolver 缓存契约。
- 当前 model 已带完整线路时，现有 memo 的原始 model 键不能被 canonical 替代；后续真新增计价输入时才扩投影、memo 和可恢复事实。冻结保存自己的目录/版本，实时变更不能进入旧冻结。

### 3.4 重试与发现范围

复用 24h 成功更新、1h 失败重试。无能力变化的 unsupported-provider/非法名称不因每次观测或全局 force 重新执行无效发现；解析规则修订或明确身份映射变化后重新评估。全局 force 仍可刷新既有受支持价目所需的源，不要求全局强刷零网络请求；不能仅因一个拒绝目标额外抓六源。用小的解析能力修订值及实际映射签名即可，不建能力注册中心；普通报价更新不是解析能力升级。

网络/临时解析错误按 1h 可恢复；not-found 按目录正常更新周期再查。来源冲突不能永久封死，后续有效源快照可重新评估。retryable/nextRetryAt 必须和调度共用同一判定；第一批显示“最早可重试”，第三批才保证服务运行时的后台检查。交付 timer 后不能 UI 说一小时而实际六小时才检查。终态指本次能力下不可处理，不是永久黑名单。

第四批首轮只支持**已证实的一组 provider/线路映射**，在 K08 固定 fixture 与明确目标；优先走已有 models.dev / LiteLLM 下载和校验。不是一次支持所有提供商，也不把公开目录的 provider 自动等同卖家。官方 HTML 新解析器、更多 provider 是同粒度后续卡，未派发就不包含。

## 5. K：计价内核 worker 小卡

- **验：** 同 token 两条线路不同金额；改普通模型价不覆盖线路价；缺 Fast 场景未定价且不 ×2。明确免费不被 routes 覆盖，旧厂商特例不被通用规则吞掉。

### K05 — 缺价改为未定价

### K06 — 费用版本与 memo

- **做：** 生效 routes/政策/绑定进入费用版本，日期/错误状态不冒充费率修订；核对原始线路 model 的 memo 区分、目录重置及缓存失效。实际新增输入才扩 memo 键；完成后向 D06 交版本输入清单，K06 不等待 D06。
- **验：** 线路 A/B 不共用错误金额；改线路费率后重算；仅改证据日期不必重做费用。冻结路径由 S02 验，不在本卡包办 store/server。

### K07 — 现有三路费用对拍

- **依赖/文件：** K05/K06、D07、A10、S01/S02；three-path-parity 和确受影响的 pricing 测试。
- **做：** 扩展现有夹具，比较原始/索引/浏览器既有计算路径的线路、免费、缺价与查询范围；不新建一套估算器当 oracle。

## 6. D：存储与服务 worker 小卡

每卡 15–20 分钟。D 绑定 Price-worker-B，当前实际派发见执行记录。

### D01 — 暴露真实价格与 FX 状态

- **依赖/文件：** 无 K 依赖；pricing-store.js、pricing-store 测试。
- **做：** 返回已持久化但未公开的 pricePartialFailure；补 exchangeRateOrigin，保留各自 attempts/updated/date/issues。内置 FX 不能冒充已成功自动报价。
- **验：** 价格成功 FX 失败、部分价格源失败、纯内置三例；失败保留旧有效值；statusVersion 覆盖这些可见状态。给 A02 真实响应。

### D02 — 普通模型字段覆盖与撤销内核

- **依赖/文件：** K01；pricing-store.js、pricing-store 测试。
- **做：** 保存时按当前有效目录识别实际编辑，保留未动的手动字段；接 restoreFields 删除指定模型覆盖，重组校验后原子发布；新自定义条目移除不影响内置。
- **验：** 自动价追平手动价后仍保留手动字段；未覆盖字段继续自动变化；撤销取最新底值；写盘失败不改生效价/原文件。path 必需校验跟本卡，不推给 UI。

### D03 — 模型编辑 API 接通与并发保存

- **依赖/文件：** D02；server.js、pricing-api 测试。
- **做：** GET manualOverrides、PUT restoreFields 接既有保存入口；版本校验覆盖实际提交临界区。两个 PUT 或 refresh+PUT 不丢字段。接通旧客户端格式，不新开端点。
- **验：** 同版并发写只能按约定成功一次/另一份 409；非法字段拒绝且不写盘；刷新与手动保存交错后手动字段仍在。A04 可开始实际联调。

### D04 — 终态、冷却与能力变化重新评估

- **依赖/文件：** D01；pricing-store.js、server.js 的 discovery 调度、各自测试。
- **做：** 缓存拒绝原因及小的能力/映射签名；无能力变化不重复发现。网络失败可重试，not-found 随目录更新再查；向 UI 给出与实际 due 逻辑一致的 retryable/nextRetryAt。
- **验：** 重复观测不因 unsupported-provider 重拉六源，全局 force 也不绕过该目标的能力拒绝（受支持价目刷新仍正常）；网络失败到期再试；解析修订/明确映射变更后可重评。不要只改 store 而让 server 的旧 missing 调度继续空转。

### D05 — schema 3 兼容读取及叠加

- **依赖/文件：** K02；pricing-store.js、pricing-store 测试；夹具可提前准备。
- **做：** load/automaticBase/applyCurrent 支持 routes+routeOverrides，分别叠加；兼容旧文件与旧自动缓存，未知版本/非法新增字段明确失败且不重写。
- **验：** schema 2、旧全量、schema 3、无 routes 缓存各可加载；线路自动底值+手动单字段只覆盖该字段；只读加载文件字节不变。

### D06 — 线路持久化、撤销与版本

- **依赖/文件：** D05/D02、K06 的版本约定；pricing-store.js、pricing-store 测试。
- **做：** 保存 schema 3 的 routeOverrides，沿用 D02 的编辑/撤销语义；自动路线缓存与手动覆盖分层；effectivePriceVersion 纳入实际影响费用的 routes/政策/绑定。
- **验：** 保存重开不丢 modelOverrides；手动覆盖字段不被自动价分叉替换，撤销恢复最新自动值；仅核验日期变化不报告费用改变。原子失败路径沿用，不另写一套。

### D07 — 线路 API、覆盖与载荷边界

- **依赖/文件：** D06、K03/K06；server.js、pricing-api 测试。
- **做：** GET/PUT routes、线路 restoreFields、usageCoverage 与 snapshot catalog 接通；省略 routes 保持原目录，显式空对象才按空目录处理。请求体保持明确上限并报超限；2026-10-24 主审实测后决定仅价目 PUT 从128提升到256 KiB，依据见下。
- **验：** 模型 256/线路 512 独立计数；使用代表性接近上限数据实测字节，条目合法但载荷超限明确失败、不丢旧值。若正常代表性配置确实超 128 KiB，由主审记录测量后决定一个明确新上限，不默认扩容；本卡不靠截断成功。

容量决定：按A实际保存载荷形状，256模型加512普通完整线路为原始158,829字节、规范化175,518字节；128 KiB不能承载正常代表性配置，256 KiB足够。只调整价目PUT，其他入口不变；还须验证合法字段构成的超256 KiB载荷明确413且旧值不变。

### D08 — 刷新按需抓源与共享到期判定

- **依赖/文件：** D04；pricing-store.js、pricing-store 测试。
- **做：** 对价格/FX/发现按实际 due 与目标需要选择已有 fetcher；发现一个缺价不使所有六源无条件刷新。保留 24h/1h、失败旧值与原有厂商抓取规则。
- **验：** 价格未到期但 FX 到期只抓 FX；已知目标只抓需要源；错误后 1h 到期、成功后 24h。测试计数实际 fetch 调用，不用只返回“跳过”但已经抓取的伪优化。

### D09 — 独立后台定时与生命周期

- **依赖/文件：** D08；server.js、pricing-api/server 测试。
- **做：** 启动加载完成后做非强制到期检查，之后每 1h 检查或精确安排 next due；复用 requestPricingRefresh 并发合并，不建第二刷新队列。定时器 unref，关闭取消且不重排，沿用实际 close 等待语义。
- **验：** 可控时钟验证页面关闭仍更新、24h 成功/1h 失败；UI/usage/timer 同到期不重复并发；服务关闭后不再回调、CLI 不被留住。不能用真实等一小时来验。

### D10 — 首组自动候选入库与手动共存

- **依赖/文件：** K08 冻结候选输出、最终接通等 K11，另需 D05/D06；pricing-store.js、pricing-store 测试。
- **做：** 将确认目标分别发布到自动 models 或 routes，复用校验/原子写入；证据状态不越过手动字段。源冲突保留上一有效自动值，无旧值则未知；手动差异只作提示。
- **验：** 自动价更新而手动单字段不变，其他字段更新；冲突不污染缓存/覆盖；未知币种或不完整候选不入库。返回目标级结果供 A12 使用。

### D11 — 行级非强制刷新 API

- **依赖/文件：** D10、D08；server.js、pricing-api 测试。
- **做：** body.model 精确目标与 force:false；复用缓存及现有来源下载。并发合并保留各目标的并集和全局 force 语义，不能丢失排队目标；行级不顺带刷 FX。
- **验：** A 请求不会触发 B 或全局六源；缓存可用时不重复下载；并发 A/B/全局请求不漏目标、不串返回归属。非法/歧义名按约定拒绝或保持未知。

## 7. S：主审接线与独立验收小卡

主审也按 15–20 分钟单元处理，不把所有共享文件和最终修复攒成一张大卡。下列为必要接线/收口；发现跨线锁或新的缺口时，先说明最小接点，再按同粒度拆后继，不能自行扩成历史保留重构。

### S01 — 实际费用输入与热路径

- **依赖/文件：** K03/K04；读 usage-core/types/store/executor；只改缺失接点及一个专用定价集成测试。
- **做：** 核对原始 model 在事件、IndexedCostEvent、范围/时间图/明细/导出投影中是否保留完整线路。首版不新增 route 字段或请求关联；已有字段足够则只补回归。
- **验：** 两个同 canonical 的完整原始线路进入各路径仍可区分；聚合未保真时费用保留现有逐事件路径。若实际缺失不止一个接点，按路径拆后继，不一次改全部 usage 模块。

### S02 — 重算缓存与冻结隔离

- **依赖/文件：** K06、D07、S01；主审协调 D 的 server 只读/短时移交，需要的 usage 缓存接点与专用测试。
- **做：** 核对有效费用版本在 executor、prepared/memo、查询响应与快照中传播；价目保存后失效实时费用，不改事实。旧冻结固定原目录/版本，不能先用全局 setPricingCatalog 并发污染别的请求。
- **验：** 改线路费率后实时所有费用视图一致变化，旧冻结一致不变；只改状态日期不误失效费用。发现全局目录临界区问题只修该接点，不做全服务并发框架。

### S03 — 冷热/恢复等价

- **依赖/文件：** S01/S02、D06；历史归档/保留现有夹具与一份定价集成测试，需先核对锁。
- **做：** 验完整原始线路事实及价目/覆盖在热冷跨界、备份恢复、原日志缺失时足以按 C 重算。已有投影足够时不迁移、不改 rollup。
- **验：** 同一数据冷热/恢复前后的 token、已定价合计和未知份额一致；有效目录/手动配置随现有备份约定可恢复。发现缺目录或事实字段则拆一个明确补齐卡，修好才过 G2；不能仅验证热库就勾冷恢复。

### S04 — 分批独立产品验收

- **实际单元：** S04-G1、S04-G2、S04-G3、S04-G4 各约 15–20 分钟，分别记录状态，不能把四次复核合并派发。
- **依赖/文件：** 当前批次的必要 A/B/S 卡就绪；只读 diff、实际临时服务与测试。
- **做：** 每个 G 分别执行一次本卡；G1 核普通模型保存/撤销与状态，G2 核线路/缺价/冻结，G3 核调度，G4 核首组来源与行级刷新。A 的结论由主审独立核，不照抄外部 LLM 报告。
- **验：** 针对本批 1–3 个关键反例复跑并记录接受/待修项。每次只收一个 G；四批复核不是同一张 20 分钟任务。失败回所属卡，不在本卡顺手完成全部返工。

### S05 — 工程检查收口

- **实际单元：** S05-static（静态检查）与 S05-tests（全仓测试及失败归属）分别执行、分别交接；失败修复不并入检查卡。
- **依赖/文件：** 本次约定交付批次通过；主审统一运行，不与 worker 的全仓检查抢跑。
- **做：** 运行 typecheck/lint/format:check 和测试；静态检查与全仓测试分别作为一次检查单元，耗时明显超出单卡则分次报告，不让 worker 等“最终大包”。既有失败和本次失败按证据分开。
- **验：** 记录实际命令、结果和未覆盖点；失败的修复另开所属模块短卡。只改本次问题，不全仓格式化，不用旧全绿记录替代本轮。

### S06 — 计价说明与交付状态

- **依赖/文件：** 对应 G 与 S05 结论；docs/11-pricing、索引/任务入口。
- **做：** 按实际交付范围更新 API 等价估算、C、合计含义、手动/自动/撤销与刷新；写明首组支持范围、仍未知项和实际验证限制。
- **验：** 文档不再声称缺价默认最低价（仅在 G2 交付后改）；未完成调度/provider 能力不提前宣称支持。设计方案原调查价格快照不改成最新报价。
