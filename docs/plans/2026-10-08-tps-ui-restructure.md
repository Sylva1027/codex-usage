# TPS 前端重构：模型平均速度与联动详情

日期：2026-10-08。状态：前三版被否决；本轮按用户明确的内容要求重做交互原型，正式页面尚未替换。

2026-10-09补充：用户明确拒绝渐变速度条；原型已改用现有主题强调色的纯色填充。

原型上方静态演示的横条也取消了遗漏前景色产生的渐变；这是演示页修正，正式实现仍只设置新模型速度区域的填充，不改原页面其它区域的既有颜色。

## 用户已明确的要求

- Agent 指 Codex、DSH 等工具。主/子代理不放在概览里。
- 左侧展示模型原名、推理强度、所选时间范围内的平均速度，默认由快到慢排序。
- 概览不显示样本数量。推理强度独立成列，不能拼入模型名称。
- 右侧保留10%/90%分位和有效样本数；其内部排版必须沿用项目现有UI语言。
- 左右速度条只用现有主题强调色的纯色填充，不得出现光谱渐变或继承bar-fill的默认渐变。
- 独立区域复用上方“时间分布—详情”的概览与详情关系，保持原有宽度比例和间隔。
- 来源选择继续使用扫描目录编辑窗口。不重复来源筛选、添加快捷入口或另做下拉框；时间范围已经在顶部选定，不在本区域重复显示。

原M5的性能标签和诊断墙，前两版的全宽单表/并排目录卡，以及第三版的样本列、复合模型名称、字母排序、p50主数字、右侧小字指标格都停止作为执行要求。内部统计字段不能直接决定产品布局。旧技术门禁只证明其对应版本的技术结果。

## 具体呈现

区域位于模型/仓库周期表之后、扫描目录之前。标题用“模型速度”，右上角不再重复写本周、日期或统计口径。

左侧复用现有comparison-table凹槽、字号、行高、数值按钮与排序表头，四列依次为：模型、Agent、推理强度、平均速度(tok/s)。模型单元格只放原始模型名；Agent单元格只放工具名；推理强度保留实际记录值，未记录时显示“—”。长模型名按现有规则省略，原名可通过title与右侧读取。

默认按未舍入的平均速度降序显示，速度表头明确显示向下排序指示；沿用现有表头交互可切换方向。显示一位小数，平手按稳定key排序。横条和数字共用速度单元格，横条对应速度值，所有左侧行使用同一刻度。没有有效数值的行排在末尾并显示“—”，不当成0，也不以小样本阈值改变排序。

速度填充统一使用现有主题强调色var(--blue)的纯色，与速度数字一致。复用bar-fill时须在新区域作用域内明确设置background，避免继承底层linear-gradient；不改变原页面其它区域的配色。正式浏览器检查必须断言左右全部速度填充的background-image为none，深浅主题都要检查。

悬停、点击、键盘聚焦模型行都更新右侧；移开指针保留最后选择。上下键移动行，Enter与Space使用原生按钮行为。右侧直接复用上方详情的bar-list、bar-row、bar-label、bar-name、bar-value、bar-track和bar-fill，使用其现有16px标签、10px行间距与横条材质，不再自创11px指标格或嵌套统计卡片。

右侧依次显示模型、Agent、推理强度三条标签/数值，再显示平均速度、10%分位、90%分位三条带横条的数值，最后显示有效样本数。分位与均速共用右侧刻度，不给样本数画速度条。全部数值来自同一选中记录、同一时间范围和同一来源选择；不加默认警告墙。

无数据时只在左侧保留一条对应状态，并隐藏右侧、取消空状态最小高度。正常布局复用main-grid的左侧跨两列/右侧占一列；内部内容多时按既有规则滚动，窄屏沿用原断点。上方时间分布及其三个切换继续独立工作。

## 平均速度及记录粒度

平均速度不是p50。正式实现使用所选时间内有效记录的输出tokens总和除以观测耗时总和，单位tok/s，与现有tps.pooled的计算一致。不能把现有p50改个标签称为平均速度，也不能平均各明细组的p50或pooled值。

一条概览记录对应“工具(sourceKind)、模型原名、推理强度”。扫描目录、渠道、provider与主/子代理身份不作为概览行的拆分条件；已通过现有选择流程的这些记录均参与所属工具/模型/强度的历史统计，不为简化显示而删掉子代理数据。不同工具、模型、推理强度各自保留一条记录，不将其混成一个数值。

这是新增的工具/模型统计投影，不能仅隐藏原groups中的身份字段而留下多条外观相同的行。现有明细groups及归属、发布、去重、时间过滤规则保留；在相同的已选择有效记录集合上重新计算新投影的平均速度、p10、p90和n。p10/p90沿用现有nearest-rank算法，对所属记录的原始速度集合计算，不能由原明细组的分位数拼接推导。

现有来源链路已核实：[扫描目录编辑](../../public/app.js:3836)更新excludedHomes，[请求组装](../../public/app.js:4196)发送exclude，[服务端](../../src/server.js:121)同步过滤用量与perfSamples。新投影必须消费同一条选择链路；不在前端重新读日志、不另建名单、不增设轮询。

## 正式实施顺序

只交TPS-worker (3)，不向worker 2派发。本轮先交付可查看的原型；正式实现按以下三块顺序完成，不能直接照搬模拟数据。

1. **工具/模型统计投影。** 在src/perf-stats.js复用现有有效记录选择及统计归约，新增summary.perf.models：每项包含key、sourceKind、model、reasoningEffort、averageTps、p10、p90、n、state。均速用记录级输出/耗时总和计算，分位用同一集合的速度计算，保留已有数值溢出规则。src/usage-core.js的buildPerfStatsBlock是内存/store共用入口；同时接入两处公开summary投影、补充usage-types.js，不改SQLite布局或原明细groupKey。rebuilding时新数组也为空，不能残留旧数字。验证跨home、主/子代理进入同一工具/模型/强度行，工具或强度不同则分开，输入顺序不影响结果；用耗时不同的记录证明均速不能被平均p50替代，并验证分位、n与均速集合一致。
2. **展示与交互。** 在public/perf-ui.js、index.html、styles.css、i18n.js实现上述四列表与右侧bar-list，复用现有组件样式。删除旧性能标签及嵌入时间分布的性能DOM，保留原时间分布和用量详情。app.js/app-state.js移除performance activeView分支，新区域随原render/loadUsage消费perf.models；只保存选中key与排序方向。数据刷新时校验选中key，失效则选有效记录或清空；悬停不重建左侧，不扰动时间图、焦点或滚动。排序后恢复表头焦点；hidden状态须覆盖detail-panel的display:flex。
3. **检查与交付。** 更新受影响统计/API/UI测试，证明内存与store新投影一致。通过原扫描目录编辑窗口验证同一次exclude同时影响用量与速度；检查日期/时区/冻结、均速排序、未知强度、null/overflow、选中失效、双语、主题、鼠标与键盘。1440/1024及窄屏留完整截图，对照上方两框的横向位置、宽度、右侧标签字体和横条；对照模型表的行高/字号。运行受影响测试和typecheck/lint/format，新门禁绑定实际产品文件版本。

执行者提交一份滚动报告，包含改动、截图、尺寸对照、命令/退出码和未完成项。演示状态按钮、模拟记录及静态时间图不能复制进public。正式落地后同步看板与README入口；旧M5/M8证据保留版本归属，不以原型检查代替真实接线检查。
