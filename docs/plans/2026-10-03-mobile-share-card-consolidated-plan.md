# 分享图片融合计划

更新：2026-10-05。状态：**只做计划，未实施**。这是分享功能的唯一现行计划，融合四份参考稿的有效设计与工程建议，并纳入用户本轮产品取舍；原稿见[归档索引](../archive/2026-10-03/00-index.md#分享参考稿)。已确认方向与推荐细节分别标明；确认设计方向不代表进入实现。

## 已确认的需求与场景

用户希望一键生成美观、有设计感、小块化且只展现关键信息的分享图片。**接收者以普通人为主**，无需熟悉看板、Token 明细或计价规则也能读出这段时间的使用情况。设计语言延续软件的陶瓷材质、主题色和可选角色。

2026-10-05 已确认：

- **信息重点：总用量为主数字，常用模型为第二重点，费用默认关闭且开启后仍为次要信息。** 使用通俗短标签和必要释义，不以专业指标数量体现信息量。
- **支持有限的半自定义。** 用户可以调整少量内容与表达，初始成品仍可直接保存；具体控件范围见下方建议。
- **主题跟随当前界面皮肤，分享图片统一使用该皮肤的浅色配色。** 深色看板也生成同一皮肤的浅色图；本轮问答已确认这条规则。
- **人物占角部或侧边的一定面积，提供辨识度，保持内容为阅读中心。** 不将人物提升为视觉中心；关闭时完全不绘制，仍保留对应主题色。
- **不设置独立的文案标题及标题编辑。** 周期、日期和指标标签提供信息定位，中英文均需清楚、简练。此前个人化抒情标题的建议已撤回。
- **辅助指标最多展示两个，但选择范围不能过窄，缓存命中率纳入首版可选项。** 普通人受众决定默认层级与释义，不用于删去用户在意的技术指标。
- **拟建立新的独立产品品牌，名称待定。** 当前通用名称不作为分享卡的最终品牌；产品表达与软件许可信息分别处理。

主页、设置和分享弹窗运行在 PC，主要面向 16:9 高分辨率桌面大屏与鼠标键盘操作。手机阅读要求只针对生成的图片，不扩展为整套软件的手机页面需求。桌面缩放、侧栏、并排与短窗口按[开发基准](../03-development.md#界面设计与验收基准)验收。

旧独立 HTML 导出已移除。本方案不接入旧打包器，不恢复离线网页分享；暂停自动刷新的服务端冻结快照仍是现有功能，见[开发说明](../03-development.md#旧-html-导出与历史验证)。

## 推荐画幅与内容

默认样稿推荐 **3:4 竖版、1080×1440**，比例均按宽:高记。它适合手机图文信息流，也便于将主指标和少量辅助卡片纵向排布；不将 16:9 横版作为默认分享图。

4:5（1080×1350）保留为紧凑对照样稿；1:1 可在后续需要极简分享时独立构图；9:16 留给全屏海报，不要求第一版同步实现。4:3 是横版，可另按横向内容需求评估。先确认默认 3:4 的效果，再决定格式数量。

内容按以下阅读顺序组织：

1. **周期与截止时间。** 用紧凑的周期标签和实际日期交代内容，不另加抒情标题、口号或可编辑的文案栏。展示真实统计区间与所选时区；自然周、自然月和 Codex 限额窗口分别命名。进行中的周期标注统计截至时间。
2. **总用量主数字。** 数值和 Tokens 单位分层，推荐短标签“AI 用量”，配必要的通俗释义。保留真实量纲，不将 Tokens 换算为字数、代码行数、工作时长或效率；费用、环比与纪录不争夺主数字。
3. **常用模型专区。** 作为第二重点单独排布，推荐展示所选区间内按 Tokens 用量排序的前三个模型；模型少时自然收缩。主模型更醒目，名称与必要的用量信息足够，不堆长表格，也不把用量排名解释为调用频次、使用时长或效果排名。
4. **最多两个辅助小块。** 推荐默认会话数、模型数两块；允许从下方的较完整指标集合中替换或隐藏。每块只放短标签、数值和必要说明。模型总数覆盖整个所选区间，不能等于展示的前三名数量。缓存命中率首版即可选择，不因其偏技术而延后。
5. **可选费用与小型页脚。** 费用默认关闭；开启后放在次要行或页脚区域，不占用主数字、常用模型或两个辅助位置，不通过字号与强调色提升为主信息。保留“API 等价费用估算”“非实际账单”；存在缺价、最低费率或未计价时保留对应限定。USD/CNY 沿用现有换算规则，关闭费用后释放空间。新品牌标识方式见下方建议。

走势合并保持原总量、时间顺序与完整区间覆盖，并标注实际粒度；没有可比较上期时不展示环比或 New Record。零用量与数据缺失分开，未知缓存率显示“—”。小数值可使用原数或 K 等直观单位，验证换算与舍入，不要求逐字符照搬看板的 M/B/T 显示。

首版推荐围绕主数字、常用模型和辅助小块收敛。迷你走势、纪录与环比属于后续内容候选，不因看板已有数据就自动加入分享图。

## 半自定义范围建议

有限自定义已获用户确认；下面是推荐的具体范围，仍可通过样稿调整。

- **人物。** 有角色皮肤时提供显示/隐藏，初始跟随当前看板人物偏好；classic 无人物控件。分享构图中的人物强度独立设计，不直接继承看板背景角色的透明度或坐标。
- **费用。** 默认关闭，临时开启后带必要限定；不允许为了版面隐藏估算性质或缺价说明。
- **辅助指标。** 最多两个位置，分别选择指标或隐藏，避免重复选择；隐藏后自动收拢布局。推荐首版提供会话数、模型数、缓存命中率、总输入 Tokens、缓存读取 Tokens、缓存未命中输入 Tokens、输出 Tokens、推理输出 Tokens，共八个候选。

指标候选沿用现有统计和可信明细。缓存命中率按总输入与缓存读取均已知的记录计算，为累计缓存读取除以累计输入，不平均每条记录的百分比，也不以是否展示费用决定其可用性。缓存未命中输入只在相应明细可信时计算；推理输出保留其为总输出子集的口径。分母为零或数据不可用显示“—”，部分明细应保留简短的范围限定，不能伪装成完整统计。是否纳入其他已有指标，在样稿中评估信息价值与可读性，不新增无法由现有记录可靠支持的量。

总用量、真实周期和必要的数据说明保留为稳定骨架，常用模型默认展示为第二重点。主题身份由当前皮肤带入，不在分享弹窗另做一套皮肤选择器。第一版推荐不提供任意拖拽、自由坐标、色板、字体、人物透明度、背景上传或主指标替换；文案标题与标题编辑已从本计划移除。

初始预览具备完整成品；推荐先显示人物与费用控件，两个辅助指标选择放在可展开区域。调整只影响本次分享，不写回主看板的皮肤、人物或统计选择；暂不要求分享设置持久化。

## 主题组合与人物构图

完整十角色范围下，共有 **21 种浅色主题组合：1 种 classic + 10 套皮肤 × 人物显示/隐藏**。这是主题与人物状态的组合数，辅助指标、费用等内容变化另计，不表示制作 21 套互不相关的版式。

人物显示时位于分享卡的某个角或一条侧边，占据足以辨认人物的一定面积，采用贴边或局部出血等方式融入卡片。面积不等于视觉优先级：主数字、常用模型和辅助信息保持清晰完整的快速阅读路径，人物不成为视觉中心，不遮盖或穿过数字、模型名、日期与说明，也不迫使内容缩小。具体角位、边位、裁切和强度通过样稿比较。

人物隐藏时不绘制残影、轮廓或人物水印；沿用该皮肤的主题色、表面冷暖和材质，形成隐性的身份表达。显示/隐藏共用稳定的信息层级与品牌标识规则；隐藏后收回人物占用的边缘空间，避免留下空位。此前“人物与主数字共同形成视觉中心”的建议已被本轮角部/侧边方向替代。

图片主题身份始终取自本次打开时的当前皮肤，色源和角色素材明确选择 `light`。即使主界面为深色，弹窗继续使用主界面模式，预览与保存的图片保持浅色；不得为了生成图片临时切换主看板的主题。

颜色沿用届时生效的正式皮肤输入与公共派生规则，和[皮肤配色方案](2026-10-03-skin-palette-consolidated-plan.md)保持同一来源；不冻结旧色值，也不维护另一套分享色板。十角色是完整目标，实际接入与检查需记录当时已开放的皮肤范围；当前选择器未开放的皮肤不因本计划自动上线。

## 信息标签与新品牌建议

本卡片采用简短的信息标签和清晰的数字层级，不设独立的抒情标题，也不将此前“与 AI 同行”等句子换名为副标题后继续保留。周期、实际日期、总用量和常用模型已足以交代内容。中英文分别处理标签长度与换行，不机械直译，也不默认同时铺两套文本。

用户提出独立命名与品牌传播方向，最终名称尚未确定。后续命名应有辨识度、便于读写与记忆，中英文能自然使用，并容纳多来源用量、主题角色与未来功能；功能解释可以由一句简短产品描述承担，不要求名称直接堆叠 Agent/Usage/Codex 等通用词。当前 Agent Usage 仅代表现有实现名称，不据此锁定分享卡的最终品牌文案。

推荐在样稿中先预留小型品牌字标或标识位置，使用明确的待定占位而非自行取名；优先比较短字标本身与简短生成署名，最终措辞、位置和是否可隐藏仍待新名称与样稿收敛。通过统一陶瓷材质、数字排版、角色边缘构图和标识位置建立辨识度，不添加大水印、未经确认的网址或二维码。分享卡和日常产品展示围绕新品牌，不要求展示原项目名称或宣传原作者。

品牌独立与代码来源按各自事实处理。2026-10-05 核对仓库[LICENSE](../../LICENSE)为 MIT：许可允许修改与分发，同时要求在软件副本或实质部分中保留原有版权声明与许可文本，见[OSI 许可原文](https://opensource.org/license/mit)。后续可建立自己的名称、定位与维护方向，但不删除仍适用于继承代码的原许可信息，也不把历史代码来源改写为全部原创。许可证与来源说明在仓库或法律说明中处理，不作为分享卡的推广内容；本轮不修改 LICENSE、README 来源说明、仓库名或命令名。

## 视觉与阅读尺度

沿用当前皮肤的浅色配色及公共派生、现有字体和圆角，形成柔和基底、凸起小块、局部凹槽与主题色点亮。保留统一的左上光源，逐套检查高光、投影和角色线稿，避免材质压过文字。主界面深色不改变图片的浅色规则。

人物辨识度通过角部/侧边的一定面积、清楚的线稿和合适裁切建立，视觉权重服从数据的快速判读。优先保护可辨认的面部与轮廓，不拉伸素材；不因角色需要额外抒情文案或中心人物区域。不冻结旧稿的 62% 阈值、固定 hero 高度或卡片坐标。

成品分别在约 360px 显示宽度和约 160—190px 的缩略图宽度下检查。点开图片可直接读出关键标签、数字、常用模型与限定；缩略图优先保留周期与主数字，人物开启时在角部或侧边可辨认，但不压过数据。1080px 原图中的 24px 字缩至 360px 仅约 8px，不能只凭原图字号下限宣称可读。

边缘留白先以各方向尺寸的约 6%—8% 试排，关键信息不贴边或落在底部角落，装饰可出血。这些尺度均为测试起点，不是平台固定规格，也不保证所有入口都不会裁切。放不下时减少模块，不整体缩小文字。

## PC 生成流程

1. 用户在看板选好范围和来源，点击分享入口。
2. 弹窗打开即生成预览，无需再次点击“生成”；推荐 PC 左右两栏，预览和设置并排。
3. 打开时固定当前已生效的汇总、周期、来源、截止时间、皮肤身份和界面语言，并选择该皮肤的浅色配色与素材。后台刷新或看板状态变化不改变本次图片；重新打开取最新选择结果。
4. 修改辅助指标、费用、人物或已支持的格式后重绘；只提交最新一次调整的结果，保存使用当前预览的同一渲染结果。
5. 图片就绪后保存 PNG；关闭恢复入口焦点，Escape 和 Tab/Shift+Tab 沿用现有弹窗规则。

费用默认关闭与统一浅色规则已确认；入口位置、图标和控件组织待样稿收敛。分享入口不重排主看板。窗口空间受限时允许局部滚动或必要的排列调整，不新增手机操作界面。

PNG 保存是核心流程。复制图片和系统分享面板作为后续增强，分别做能力检测及失败降级；不保证任何浏览器环境下保存、复制或系统分享都无条件成功。生成失败显示可读原因与重试，不下载半成品。

## 工程建议

优先评估本地 Canvas 2D，以同一渲染结果承担预览与 PNG 输出，无需增加运行依赖。先验证真实文字、线稿和陶瓷材质效果，再定实现细节。

- **纯数据投影与布局/绘制模块。** 可新增 `public/share-card.js`，接受汇总、固定的浅色主题输入与明确的展示选项，支持人物显示/隐藏两种构图，不访问原始日志、DOM 或全局页面状态。
- **页面控制。** `public/app.js` 负责固定汇总与皮肤身份、取得对应浅色配色、加载浅色角色、传入语言/货币/时间/指标标签、弹窗状态与文件保存。沿用 `skinRuntime.urlsFor(skinId, "light")` 和本地素材，不读取已删除的内嵌资源全局变量。主题身份与图片模式分别传递，不能直接复制深色页面的计算颜色或短暂切换主界面来取色。
- **样式与入口。** 在 `public/index.html`、必要的 `public/share.css` 和 `public/i18n.js` 中接入同款控件、状态提示、焦点恢复与可访问名称。新文案遵守现有 i18n 测试。
- **色源映射。** `--neo-raised`、`--neo-inset` 是 CSS 阴影字符串，不能当作 Canvas 色值；读取面板、边缘、明暗色源，重组填充、渐变和投影。计算颜色需验证实际返回格式与透明度。
- **数据白名单。** 只收汇总数字、必要模型名、时间、指标标签与限定说明；路径、来源目录、会话 ID、正文、原始事件不进入分享模型，不为已移除的标题编辑增加自由文本字段。

不为了出图重新扫描日志、另建统计规则、增加账号或上传服务。第一版不做公开链接、二维码、GIF、任意长图、独立色板或分享设置持久化；这些是推荐范围，不是永久排除后续需求。深色图片不进入本版范围。

## 后续阶段与验收

**P0 方案收敛。** 普通人受众、总用量/常用模型重点、费用默认关闭且保持次要、有限自定义、皮肤跟随且统一浅色、人物占角部或侧边并可完全隐藏、缓存命中率首版可选、无独立文案标题已确认。继续收敛具体辅助指标集合、新名称与品牌标识、入口和格式范围；当前只做计划，未进入编码。

**P1 视觉样稿。** 用同一组合成数据先比较 3:4 的人物角部与侧边构图、隐藏人物的主题色构图，并包含 classic 基线。采用少量有差异的代表皮肤比较，不让用户一次筛选 21 张近似方案；构图收敛后再检查完整主题范围。展示默认成品与典型半自定义结果，包括缓存命中率和开启后保持次要的费用，以及新品牌标识占位；不制作抒情标题或中心人物版本。必要时对照 4:5。同时展示 PC 弹窗与成品的手机阅读、缩略图尺度，确认后再冻结布局。

**P2 核心能力。** 完成白名单投影、浅色主题映射、有限自定义、预览和保存 PNG、状态与异常处理、焦点及中英文。单元测试重点验证范围和来源沿用、总量保持、模型排序、缓存率加权与有效明细范围、候选指标替换、混币、缺失值、长模型名、极大数值和文件名安全；不是靠绘制调用次数证明视觉质量。
