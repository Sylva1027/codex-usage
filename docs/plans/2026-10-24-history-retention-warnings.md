# 历史保留实施警示（15–20 项）

日期：2026-10-24。性质：**只读警示，不是施工授权**；不改变 20 项分母、既有验收与文件锁。冲突时以 [Implementation Plan](2026-10-22-history-retention-implementation-plan.md) 与[执行账本](../validation/2026-10-22-history-retention/README.md)为准。每条警示均为已发生或已记录的事实，附后果与要求；无对应证据的担忧不列入。

## W1 冷区 perf/timing 没有对称契约

- **事实：** §4.1 只冻结了 events 的修订 overlay 契约；§4.4 要求 perf 样本、request timing、WorkBuddy 时长进段，但未定义它们进段后的修订与淘汰契约。账本第 80 轮（2026-10-23T15:39Z）确认 sourceEvidence 只绑定 events、物理 perf 表是否已在候选段未定，B-cold-perf-read 正在为 perf 单搭平行读取链。
- **后果：** events 与 perf 两套权威链不对称。"段里有 events 但 perf 样本缺失或无法淘汰"类缺陷会在 15/16 接线时集中爆发，或在逐卡验收中被静默放过。
- **要求：** 在任何 merge/淘汰接线卡之前，主审先冻结冷区 perf/timing 契约——进段形态、与 events authority 的绑定关系、修订 delta 是否复用同一 overlay——作为计划修订登记在案；不得用逐卡临时裁定代替契约冻结。

## W2 第 19 项没有数值目标

- **事实：** §7 只定义 WAL 稳态 <100 MB 与冷启动 <2.5 s；"百万级容量性能"在整个计划中没有通过阈值。当前实测（第 27 轮、C2 复测）首查 113.16 s、skipCheck 61.91 s，账本逐轮记录"未达整站目标"，但目标数值无处可查。
- **后果：** 没有靶子的测量无法验收，也无法判定何时允许宣称 19 完成；优化可能在错误的热点上收敛，或在没有定义的及格线前提前收口。
- **要求：** 先写数字再继续测量——1M events 下首查 p95、skipCheck 上限、峰值 RSS 的具体阈值，修订进计划后在账本登记。已定位的 minimumRatesFor 逐事件全目录扫描热点不因目标缺失而搁置修复。

## W3 已验收的是加法一半，未开始的是减法一半

- **事实：** 已完成的 14/20 全部为新增能力（保全、备份、索引、读路径、离线转移）；账本每轮重复"禁止真实淘汰"；第 79–80 轮 B-cold-perf-eviction 红卡已实际确认一个漏样本缺陷（冷 n4≠5、sampled 29≠30）。
- **后果：** 本特性最危险的路径——从热库删除数据——至今零实际执行。"按计划推进"的惯性会系统性低估 15/16 的返工量与验收密度。
- **要求：** 15/16 保持红测先行、单行为单卡；任何淘汰能力接触真实库之前必须已有完整备份与 dry-run 记录（与 W5 演练合并执行）。

## W4 跨线并行与人员退化的现实成本

- **事实：** A/C 两 worker 长期 execution-config-loading 阻塞，实际执行退化为 B＋主审串行；与 TPS 修复线在 store/core 上的并行写入已产生实际碰擦——TPS 线 3 项 parity 失败归因于本线删除语义，A7 迁移测试的 schema guard 被迫从 19 重对到 21。
- **后果：** 15/16 的淘汰语义会再次作废旧断言（同类事件已发生过一次）；无冻结协议的并行会重复支付返工成本；人手不足时把多行为捆成大卡赶进度会直接违反 §0 短卡纪律。
- **要求：** 15/16 触碰 store/core 及其断言前，与其他施工线约定共享文件冻结窗口；人手退化只允许放粗 17–19 的卡粒度，15/16 的粒度不得放宽。

## W5 首次真实封存演练与万行差额不得跳过

- **事实：** 封存阈值（≥400,000 热区 events 且最老事实 ≥180 天）意味着当前真实库（基线 87,454 events）长期不会自然触发自动封存——特性交付后最危险的生产路径可能从未真实执行过一次；I3 将"是否接入自动封存"留为开放判断。10-21/22 约 93,977 → 84,029 的差额至今未定性，§8 只要求最终"如实列出"。
- **后果：** 未演练过的自动封存等于未来某天在真实库上做首次实验；万行差额悬置会持续侵蚀"事实永不丢"这一本计划核心承诺的可信度——它就是本项目的立项动机本身。
- **要求：** 第 20 项门禁增加两张卡且不通过不得宣称计划完成：其一，"首次真实封存演练"（dry-run → verify → 新备份 → 提交，全程可回退）；其二，"真实完整包导入 staging runtime 与活库对拍"，并把对拍指向 10-21/22 窗口，给差额定性或明确划界。后者可复用第 14 项已验收的导入能力，成本有限。
