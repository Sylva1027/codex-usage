# M4.4：报告与命令小卡

适用 M4.3 验收之后。原[M4](M4-preview-and-review-tools.md)的全部行为、固定 CLI、退出码和用户选择约束保留；执行方式按[调度规则](execution-and-subagents.md)。以下七张卡分别交接，不把 M4.4 整包分派。

M4.3 当前尚在实施，`captureStateMatrix` 及 progress/capture/index 的形状以其验收产物为准。本计划不改它、不提前假定 WIP 已通过。M4.4.1 开工时只读实际接口和样本，发现冲突先停止相关接线，不趁接线返工状态执行器。

## M4.4.1 证据读取与内部接口

前置：M4.3 通过；目标仅为安全加载、规范化和冻结后续接口。

允许：新增 `scripts/skin-palette/review-evidence.mjs`、`test/skin-palette-review-evidence.test.js`、自己的 handoff/测试证据。

接口：`loadReviewEvidence({ runDir, capturesIndexPath }) -> Promise<evidence>`。evidence 含原 CandidateSet、原 Assessment/visual、逐候选 capture、原尺寸图片引用、出处和缺项，返回自有不可变数据，不冻结调用方对象。不得在读取时填 ready、执行 assess、写报告或补截图。

实现小块：

1. 从指定 run 和显式 index 读 JSON；相对路径与 realpath 均限 `docs/validation`，拒绝 junction 越界、URL、未知候选、重复绑定和含糊的多个 capture。跨批次明确引用原 run；不扫描时间找“最新”。
2. 复用 M0 校验单个候选、评审与选择。CandidateSet 结构采用 M2 已使用的 `validateCandidateSet(set, {expectedSkinIds: []})`，皮肤/候选覆盖另行核对，不强造去重掉的第三份。
3. 固定此工具使用的评审容器：`{schemaVersion:1,candidateSetHash,assessments:[Assessment],assessmentHash}`；assessments 按 CandidateSet 候选顺序且每 ID 唯一；assessmentHash 对排除自身 hash 的完整容器做 `sha256Canonical`。不改 M0 的单个 Assessment/Candidate/Selections 结构。无评审时保留缺项，不造空 PASS。
4. 固定总集出处文件 `assessment-origins.json`：schemaVersion=1，origins 按 candidateId 映射原 batchRun/capture/visualReview 的相对路径及原文件 hash。单批也可由 run+index 明确构建同样内部出处。原 recordedInputHashes/sourceHashes 不改写；总集 profiles 摘要不能冒充原批次摘要。M4.4.2 在原批次上下文核验再组成新总容器。

验收：合法单候选/局部批次样本可加载；坏 JSON、错 ID/hash、重复绑定、缺文件、真实路径逃逸均有明确结果；内部排序/hash 可复现。用临时 JSON/小 PNG 样本，不启动浏览器。完成后将 evidence、容器和出处接口写进 handoff，后续卡只读冻结接口。

## M4.4.2 离线核验

前置：.1；可与 .3/.4 并行。允许：新增 `review-verify.mjs`、`test/skin-palette-review-verify.test.js`。

接口：`verifyReviewEvidence({ evidence, requireSelections=false, production=false }) -> { status, errors, gaps, verifiedModel }`。status 固定为 pass/incomplete/rejected/invalid（内部核验结果，不改变 Candidate/Assessment 契约）；不写原始证据，不启动服务/浏览器/生成器。

verifiedModel 是自有不可变的显示/选择输入，包含 CandidateSet、复核后的评审容器、出处、图片引用、缺项和可选候选 ID。评审容器/hash 按 .1 的规则从复核后的 Assessment 重新计算；展示、选择与导出都绑定这个同一容器，不能显示新结论却带原容器旧 hash。invalid 时 verifiedModel=null；正常 rejected/incomplete 候选仍有显示模型，禁选但保留诊断。

实现小块：

1. 核对实际候选、单皮肤配方、policy/roles/derivation/fixture、必需 sourceHashes 及图片摘要；使用 M3.4 要求的覆盖集和原 capture 的自身依赖。缺摘要与不一致分别报告。
2. 在该候选真实原 batch/run 上下文调用 M3.4 复核 fast/browser/visual，不只相信落盘 `ready`。总集汇总保留原出处，再核对当前单皮肤 profileSnapshot 与公共口径；不得把总 profiles hash 强塞进原评审以消除 stale。契约无法表达相容出处时交回 .1 owner，而非修改 M0/M3。
3. 检查 M4.3 已验收的完整状态索引、浅深配对、缺测/失败、几何限制及原图。requireSelections 验证十套、真实选择来源和两个总摘要；production 验证正式身份，具体 source 变更规则等待 .7 适配。

验收：缺一必要状态、伪 ready、无视觉意见、旧源码摘要、坏 candidateHash/choices、错误 assessmentHash 均不通过；完整固定样本通过。M5 单皮肤最少两个 ready 的数量要求在批次结算验收，不把它混入单候选数学规则。

## M4.4.3 报告渲染

前置：.1；与 .2/.4 不共写文件。允许：`report.mjs`、`test/skin-palette-report.test.js`。

接口：`renderReviewReport({ verifiedModel, selectionScript }) -> string`，只生成 HTML，读写调度由 CLI 负责。只接收 .2 的显示模型，不能直接消费 loader 的原始 readiness；失败/缺测始终可见，未经核验的候选不能作为可选 ready。

实现小块：同尺寸浅深并排/模式整体网格；原图放大及诊断入口；安全文本和 JSON `<` 转义。自包含 HTML 嵌入已有原图，无远程脚本/字体；图片使用原尺寸内容，缩略展示不替换证据。不实现仪表盘、不生成新截图。

验收：一候选、双皮肤、十套三个固定样本都能显示/放大；页内正文、属性、JSON 均正确转义；一次浏览器交互验收足够，不跑颜色状态矩阵。本卡结束不得自动接选择逻辑。

## M4.4.4 选择交互与导出

前置：.1；允许：新增 `review-selection.mjs`、`test/skin-palette-review-selection.test.js`。不得与 .3 同时改 report.mjs。

接口：`buildSelectionScript(verifiedModel) -> string`；`createSelectionExport({verifiedModel, choices, decisionSource, recordedAt}) -> draft或完整记录`。只接受 .2 核验后的模型，两个入口复用同一配对/ready/覆盖规则，浏览器脚本不能有更宽松的第二套校验。

实现小块：每皮肤互斥成对选择；局部 `selection-draft.json` 与十套 `selections.json` 分离；准确绑定 candidateSetHash/assessmentHash/id/hash。输出记录操作来源，但不捏造用户消息或代选授权；完整报告导出仍等待 M5.7 对实际反馈确认。

验收：不允许 rejected/incomplete、错 hash、浅深拼接；不完整导出为 draft，十套合法样本通过 M0 校验；测试点击仅写测试目录，不向真实 run 写用户选择。

## M4.4.5 CLI 基础分发与服务生命周期

前置：.1—.4；允许：`review-cli.mjs`、`test/skin-palette-review-cli.test.js`。唯一 CLI owner，后续 .6/.7 的薄接线也由此 owner 串行完成。

实现小块：固定参数解析及未知参数拒绝；serve 调 M4.1+独立 fixture；report 调 .1/.2/.3/.4；verify 只调 .2。SIGINT/SIGTERM 和异常出口等关闭完成后清理自建 fixture；没有把浏览器业务塞进 CLI。

分发结果固定：report 对来源可信、可解析的 rejected/incomplete 模型仍生成报告和警告，禁选对应候选；文件写成只表示报告生成成功。坏 JSON、错身份/hash、路径越界等 invalid 不渲染可选报告，退出 1。verify 的 pass 退出 0、incomplete/rejected 退出 2、invalid 退出 1；不得因一个正常失败候选阻止查看所有诊断，也不得因 HTML 写入成功提高候选 readiness。

验收：短 HTTP 测试及注入 adapter 测试覆盖分发、信号、错误和 0/1/2 退出码。capture 在 .6 未交付时明确“尚未接线”退出 1，不能默认 PASS；这只是小卡的阶段结果，父 M4.4 尚未 DONE。

## M4.4.6 单候选捕获命令

前置：M4.3、.1、.5；允许：新增 `review-capture.mjs`、`test/skin-palette-review-capture.test.js`；CLI owner 单独提交薄接线。

接口：`runReviewCapture({runDir,candidateId,outDir,captureFn,fixtureFactory,resume=false})`，captureFn 默认绑定已验收 M4.3 API，fixtureFactory 默认 M0 的 createPaletteFixture；依赖注入只用于测试，生产默认不跳过步骤。候选快照、隔离 fixture、全局捕获名额、目录、清理、结果映射和显式 index 注册各走既有能力。state executor/resume 只调用，不复制。

捕获 worker 只产自己的登记分片。单次 CLI 可以在取得 index owner 后注册；多 worker 由 owner 串行合并总 index。成功项不能覆盖，失败目录保留。fixture 由本命令创建则本命令 finally 关闭；不删除来源 evidence。

验收：注入捕获函数测试成功/缺测/失败/抛错与关闭；接口样本确认 progress 和证据对应。最后一个真实候选跑一次浅深接线，已有同摘要证据且能证明实际 adapter 调用路径时复用，不为 CLI 测试重复十套。完整且无必要失败退出 0；缺测/失败 2；环境/参数错 1。

## M4.4.7 正式模式适配与集成屏障

前置：.2/.6；允许：新增 `review-production.mjs`、`test/skin-palette-review-production.test.js`，CLI owner 串行接 `--production`。

实现小块：浏览器启动前逐 token 核对所选候选与正式色源；capture 服务显式传 candidate=null，另存预期被选 ID/hash，禁止候选模块覆盖；verify 汇总正式证据、完整十套、必要状态和预期正式源变更。适配只复用 .6 与 .2，不再实现矩阵或 verifier。

验收：错 token 启动前拒绝、实际调用 candidate:null、错正式身份、缺一皮肤、候选截图冒充正式证据均拒绝。本阶段用注入 source/capture 样本；不接正式 palette、不真跑十套生产矩阵，后者属 M6。

集成屏障：协调者核验七卡接口和文件归属；四个原定命令端到端可用；三个报告规模和放大/导出行为成立；一次公共门禁，无重复完整捕获。M4.4 通过后保存工具源码快照用于 M5，任何测量相关修改按既有摘要规则重核。
