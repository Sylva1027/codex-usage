# 2026-10-02 · 页面两侧立绘随留白居中：已实施方案

状态：**用户于 2026-10-02 接受建议并要求执行；已实施、专项验证通过。** 对应[皮肤计划 §3.4](2026-10-01-model-character-skin-plan.md#34-新增需求页面两侧立绘的脸部随留白横向居中已确认)，进度维护在[皮肤 TODOs](2026-10-01-model-character-skin-todos.md)，证据见[专项验收记录](../validation/2026-10-02-skin-face-centering/README.md)。本项独立于弹窗 R6 缩略图与 S1 SpotlightCard，P4 联合验收保持单列。

## 1. 现状与原因

修复前 `public/skins.css` 将左侧图定位在 `left: 0`、右侧图定位在 `right: 0`，用 `--skin-anchor-x` 微调；`public/skins.js` 的该锚点来自整幅油墨轮廓的中心，包含头发、衣服、翅膀与尾巴，不是脸部中心。原图片位置既不读取主看板边界，也不跟踪两侧留白。旧规则现仅作为缺少标注时的降级。

源图透明留白和人物姿态各异，整幅轮廓对齐不能保证脸部对齐。用户报告约 2290px 有效网页宽度下的偏斜观感；本轮已用模拟 CSS 视口完成十角色浅深的实际渲染与定位测量，但未直接测量用户 Edge 的真实窗口，不声称已复现此前所有角色的偏移方向。

## 2. 已确认：按主看板边界取留白中点，以脸部锚点平移

**只改变人物的横向位置。** 默认 50% 透明度、当前按油墨高度归一的缩放、78vh 基础高度、底部基线、侧视左／正视右顺序保持；不改功能框体、间距、排布、源素材或弹窗缩略图。人物继续位于主看板下方，允许被框体遮挡。

### 2.1 留白边界

- 读取固定装饰层 `#skinCharacters` 的可用横向边界，以及 `.shell.getBoundingClientRect()` 的左右边界。使用同一 CSS 像素坐标系，再转换为装饰层局部坐标；不使用 `screen.width`、显示器分辨率或物理像素。
- 左侧留白为「装饰层左边界 → 主看板左边界」，右侧为「主看板右边界 → 装饰层右边界」。边界先裁到可用范围，避免无效宽度。
- 使用整个 `.shell` 的稳定外边界，不随鼠标、纵向滚动、脸部高度处碰到的某个卡片或展开内容改变横向目标。卡片间隙不作为额外留白，也不针对阴影形状逐帧寻缝。

若装饰层横向边界为 `vL / vR`，主看板边界为 `sL / sR`，则目标为：

```text
左侧脸部目标 = (vL + sL) / 2
右侧脸部目标 = (sR + vR) / 2
```

当前 `.shell` 桌面宽度规则是 `min(1440px, 100vw - 32px)`。忽略滚动条等差异时，在 2290px 可用宽度中，左右各有 425px 留白，脸部目标分别为 212.5px 与 2077.5px；在 1920px 中，左右各有 240px，目标为 120px 与 1800px。这是现有 CSS 的算例，不是用户浏览器实测；施工时只采真实 DOM 边界，不硬编码 1440、2290 或这些目标值。

### 2.2 脸部锚点

- 为十角色的正／侧视分别记录源画布内的脸部横向中心 `faceX`，采用 0—1 的归一化坐标。标的是可见脸部五官／面部轮廓的中心，不包括头发、角、帽子等外饰。
- 为窄窗口保护另记录面部横向边界 `faceLeft / faceRight`；同一坐标定义用于目检和自动测量。
- 浅深素材已有 alpha 掩码配对一致的证据，正／侧视各一套标注即可供两模式使用；实施前再次检查该前提。共二十套标注，不要求用户重画或逐图提供坐标。
- `skin-picker.js` 中已有正视缩略图的 face anchor，可作为正视标注起点，但需重新核对，不能把 stageX／top／scale 搬到主页面；侧视需要独立标注。
- 保留现有油墨量测与高度归一数据，新增独立的面部定位元数据。不能把 `MEASURED_INK.cx` 改成 faceX，否则会破坏它与量测文件的含义及校验。

若图片当前渲染宽度为 `W`，目标局部坐标为 `T`，源图脸部中心为 `f`：

```text
图片左边缘 = T - W × f
渲染脸部中心 = 图片左边缘 + W × f = T
```

CSS 可将左右两图统一为 `left: 目标坐标`，再按图片自身宽度向左平移 `faceX` 比例，取消右侧图原有 right 锚定与符号相反的补偿。公式取代旧横向补偿，不叠加两套偏移；不改变图片高度、宽高比或底部定位。

### 2.3 已确认的窄留白处理

- 留白足够时，严格对齐中点，不额外把整个人物轮廓塞进留白；裙摆、头发、翅膀可以伸到框体下方或屏幕外。
- 留白窄到容不下脸时，保持人物大小，允许框体遮住脸或身体。为避免脸同时被屏幕边缘切断，用面部边界将目标限制在「完整面部仍能处于可用视口」的最近位置；此时优先保留原功能布局，允许偏离狭窄留白的数学中点。
- 例如左脸目标仅 8px、脸部自身左半宽为 35px 时，将目标推到至少 35px；多出来的部分进入主看板下方，框体不会移动。这只是说明算法，不是固定偏移值。
- 保留现有 <=720px 隐藏立绘的规则，不新增缩小、提前隐藏或重新排列界面的断点。连续宽度变化不加缓动／弹簧，避免人物追着目标滞后。

用户已接受以上取舍；窄窗口不再缩小人物或提前隐藏，不以遮挡较多为由改变功能布局。后续仅需完成面部标注与定位效果验证。

## 3. 接入与更新

1. 在 `skins.js` 给页面立绘添加独立的正／侧面部元数据，维护量测／标注来源；不改 R6 参数、色板、素材 URL 或偏好版本。
2. 在 `skin-ui.js` 建立独立的横向定位更新：首次显示、切换角色／模式、图片加载成功、装饰层或 `.shell` 尺寸变化时重算。通过 ResizeObserver 配合 resize 等实际需要的信号，按 requestAnimationFrame 合并同一帧的测量／写入；不在 pointermove 中更新，不观察自身 transform 形成循环。
3. `skins.css` 仅调整装饰图片的横向定位规则。缺少面部标注或浏览器测量暂不可用时保留现有静态定位作为降级；无皮肤、隐藏人物、图片加载失败时不制造新可见图像。
4. 首次加载尽量在图片标为可见前完成坐标写入，避免先贴屏幕边缘再跳到中点。尺寸变化只更新定位变量，不重新下载素材、不保存计算位置到 localStorage。
5. 在线与 file:// 离线走同一元数据和定位代码；如生成配置确需新增字段，修改生成源并重跑准备脚本，不手改 bootstrap，也不写第二份参数表。

## 4. 实施后的验证

- 同时覆盖不同宽高比：2560、约2290、1920、1600、1440、1024、721、720、390px 的实际 CSS 视口宽度，以及连续缩放、浏览器侧边栏改变可用区域、滚动条出现／消失。高度变化也会改变图宽，必须重新定位。
