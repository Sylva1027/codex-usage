2026-10-01 用户反馈在用模型为空、标题视觉偏下，并要求标题与语言/主题恢复同一连续框体。原两侧独立框体规格作为先前要求保留；当前交付以连续框体为准，继续保留大号同色凹刻与顶部导入入口删除。

追加实现：先区分旧服务缺少近期字段与新版明确空名单。优先使用有效近期投影，缺少投影时使用仍可读取的最后使用时间；完全没有近期信息的旧服务暂显示已观测模型并明确提示，不能把字段缺失渲染成“暂无模型”。新版明确空名单始终有效，过期退出/静态冻结不变。补齐旧响应和混合契约回归、隔离浏览器实际列表及单框标题检查，证据另建反馈修正目录。任务见 TODO 22–26。

## 1. 执行边界与需求优先级

本计划最初在仅分析阶段建立，用户随后授权依照计划与 TODO 实施。实施沿用现有 Node ESM、原生 HTML/CSS/JS 与陶瓷材质，不引入框架、运行时打包器或外部服务。

- 最新用户要求优先于旧计划和现行专题中冲突的描述。特别是本地 Git 仓库最高优先；现行专题随本批实现同步，旧规则只保留为基线分析。
- 标题与操作按钮按追加要求共用连续框体；原独立框体要求只保留为前批历史。右侧最终仅保留语言、主题按钮；第 9 项明确删除顶部导入按钮。
- 普通时间范围按来源产品合并渠道；当前/上一完整 Codex 5h、7d 限额窗口保留渠道细分。
- Models In Use 退出只影响近期在用名单，保留原始记录、有效价目、手动覆盖和历史费用计算。
- 保留工作区原有文档移动、删除、未跟踪文件及其他用户工作；仅逐文件增量修改，不回滚旧改动，不整仓格式化。
- 验证使用隔离 home、fixture 和独立导出目录；真实索引、原始日志、价目与用户服务仅按需要只读核对。

## 2. 已核实基线

以下是 2026-10-01 的分析证据，不是后续实施完成的证明。

- `public/styles.css` 的后置 `.topbar > h1` 和 `.topbar-actions` 规则清除了框体背景、边框与阴影；标题仍使用接近正文的深色。
- 自动刷新使用 `heading toggle / last zone` 两列网格：开关被推到远端，时区在第二行且使用透明原生 select；外框没有内部状态凹槽。
- `comparePeriodComparisonRows()` 仅比较周期用量、名称和稳定标识；当前回归也断言 Git/目录按用量混排。
- `renderHomesHtml()` 直接显示内部 `home.kind`；Codex 主目录类型为 `main`，所以右侧徽标显示 `main`。
- 本地索引按 Asia/Shanghai 的 2026-09-01 至 2026-10-01 查询，与 P2 的十个渠道一致。Codex Desktop、Editor Integration、CLI、Codex Exec、codex_work_desktop 均属于 `main`；ZCode Subagent 属于 `zcode`；DSH Subagent 属于 `dsh`。
- Codex 元数据抽查确认 `codex_work_desktop` 可来自子代理，Editor Integration 的 originator 也可以是该标识。ZCode 依据 `query_source/task_type`、DSH 依据 `delegationDepth` 生成子代理渠道。
- SQLite 元数据使用全历史 `SELECT DISTINCT channel, model`；静态页面也遍历全部事件生成 harnessModels，没有模型最后使用时间与退出机制。当前已观测的 21 个模型名均在近一个月内出现，实施后无需为了演示而删掉仍活跃模型。
- 计价范围虽有 `.segmented`，但未应用 `.chart-panel .timeline-mode-select` 的完整凹槽规则。
- “流速同比”存在于渲染、翻译映射与测试；`bootDashboard()` 直接对 `#importButton` 绑定事件，单删元素会导致页面启动失败。

## 3. 九项规格与实现方向

### R1. 标题与操作区独立框体

入口：`public/index.html`、`public/styles.css`。

恢复左右两个独立容器的圆角、陶瓷表面、边缘高光和外阴影。顶层 `.topbar` 只负责两端布局，不绘制连接左右的长框。标题和按钮都必须处于各自框体内。

Agent Usage 字号以桌面 36–40px、字重 800 左右作为首轮试调起点，最终按实测确定；窄屏适当缩小。文字填色接近框体表面，用上/左暗边和下/右高光形成凹刻字，避免只给文字背后画凹槽而字形仍为普通正文色。浅深主题分别检查可读性，沿用现有字体回退，不加载外部字体。

验收：两个框体完整可见且互不连接，标题明显更大、更粗、同色凹刻；语言和主题按钮位于右侧框内，最终没有顶部导入按钮。

### R2. 自动刷新框对齐、内部凹槽与时区下拉

入口：`public/index.html`、`public/styles.css`、`public/app.js`、`public/i18n.js`。

- 外框与范围、自定义框在桌面同一行统一上下边缘；自动刷新框右边缘与页面该行右边界对齐。无错误时高度一致，错误出现时使用正常布局扩展，不能靠位移或负边距对齐。
- 框内增加状态凹槽并统一内边距；“60s 自动刷新”和开关放在一个紧邻的文本组中，上次刷新时间在下方，错误文本可独立换行。
- 时区位于框体内部右上角，与最近范围控件共享凹槽、箭头、弹出列表、悬停和选中材质。
- 保持仅 local/utc 两种状态及 `codexUsageCalendarZoneV2` 的现有持久化。local 在上海仍显示 GMT+8，切换继续影响日期解释和上次刷新时间。
- 如替换原生 select，完整迁移初始化、取值、事件、翻译和测试引用；不留下启动代码访问已删除元素。下拉支持键盘选择、Escape、外部点击关闭与焦点恢复。
- 保留轮询并发保护、暂停后的冻结快照、恢复刷新和静态快照禁用规则。

验收：桌面框体边缘对齐误差不超过 1 CSS px；手机自然换行；开关紧邻对应文本；时区在右上角且与最近范围的打开/关闭样式一致；长时间文本与错误文本不溢出。

### R3. Git 最高排序优先级

入口：`public/app.js` 的 `comparePeriodComparisonRows()`、`nextComparisonSort()`；身份依据沿用 `src/repository-identity.js`。

只对仓库表增加第一排序键：本地可信识别为 Git 的仓库在前，其他目录/未知路径在后。现有 resolver 支持 `.git` 目录和 worktree 指针文件；实施时确认已有 `kind: git` 的语义，若发现索引身份缓存与本机状态失真，记录复现并最小补齐。

组内继续使用既有规则：默认今日 → 本周 → 本月 → 全部倒序；手动表头状态以所选周期和方向为主键，平手按其他默认周期倒序，最终按显示名称和稳定标识决胜。手动升序、降序、恢复默认都不能将非 Git 目录排到 Git 组前。

保留搜索、零用量行过滤、展开详情和刷新行为；模型表继续使用既有用量排序，不增加仓库类型规则。更新仓库排序 tooltip、翻译和冲突的旧断言。

验收：低用量 Git 仍领先高用量非 Git；三态切换、切换表头、平手和搜索后都保持 Git 优先；排序不修改输入数组。

### R4. 扫描目录的 Codex 徽标

入口：`public/app.js` 的 `renderHomesHtml()` 及来源弹窗中共享的类型展示。

增加显示层映射 `main` → `codex`。已有 `zcode/dsh/opencode` 标签不变。内部 `kind`、来源 ID、限额资格和导入逻辑保持原语义；未知类型保留原有可追踪名称，不套用无依据的来源归属。

验收：Codex 主目录右侧显示 `codex`，其他三类标签正确，限额来源选择正常。

### R5. 普通范围的渠道整合

入口：`src/usage-core.js`、`src/usage-store.js`、`public/timeline-utils.js`、`public/app.js`；新增共享模块时同步接入 `src/server.js` 和 `src/static-export.js` 的静态资源/内联闭包。

普通范围归组规则：

- Codex：Codex Desktop、Editor Integration、CLI、Codex Exec、codex_work_desktop，以及有 Codex 来源类型证据的其他客户端标签。
- ZCode：ZCode、ZCode Subagent。
- DSH：DSH、DSH Subagent。
- OpenCode：OpenCode。

优先依据来源 kind/homeId 的可信映射归组，明确渠道别名用于兼容既有快照。未知或自定义项目日志没有来源证据时保留原渠道，不能把所有未知值都归 Codex。

实施方向：

1. 建立前后端共享的纯归组规则和“本范围是否归组”的判断，避免各处维护不同映射。
2. 在聚合时选用归组键；保留原始事件 channel，不重写日志和索引历史标签。费用估算仍读取原始字段，避免改变币种回退或服务档位语义。
3. 覆盖 SQLite、内存报告、压缩索引汇总和浏览器静态重算；SQL 分组与时间线事件投影都获得必要的来源信息。
4. 同步 summary.channels、各时间桶 channels、图例、详情、tooltip、颜色键和依赖渠道名的显示，使每个位置使用同一口径。
5. 会话数按现有会话身份集合合并去重；禁止直接相加已经分组的 sessionCount。
6. 通过已解析范围的 quotaWindow/quotaPreset 语义保留限额细分，覆盖 `quota_5h`、`quota_week` 以及最近范围中的上一个 5h/7d 窗口；不能仅检查按钮文字或 `preset === recent`。

验收：P2 这份已核实数据由十项合成四组；归组前后总 Token、输入/缓存/输出/推理、费用和事件数不变，会话数正确去重。限额范围仍仅统计合格 Codex 来源并保留细分；未知项目渠道不被误归类。三条统计路径同快照一致。

### R6. Models In Use 退出机制

入口：`src/usage-store.js` 的 `metadata()`、`src/server.js` 的覆盖率接口、`public/app.js` 的 `metadataFromReport()`/`pricingHarnessRows()`/计价列表、`public/pricing-models.js`。可新增纯共享模块，须遵守静态闭包约定。

默认解释：滚动一个日历月，以统一 UTC 基准计算，保留时分秒；月底回退夹到目标月最后一天。达到一整月未出现即退出，故在用条件为 `cutoff < lastSeen <= asOf`。页面选择今日/上个月或切换显示时区不会改变这一活跃口径。

- lastSeen 来自有效真实用量事件时间，按规范化原始模型名和 harness 记录；排除无效及晚于评估时刻的时间。免费规则和缺价模型也参与活跃判断。
- 在别名或后缀映射为同一价目项时，近期实际出现的任一模型名可让该价目项继续在用；多 harness 保留来源归属并继续按既有规则去重编辑。
- 保留全历史模型集合，为 All Models、历史计算和现有自动价格发现提供原信息；在用名单和在用覆盖率使用同一近期投影，不把全历史字段直接替换成近期名单。
- 明确区分“元数据未就绪”和“近期名单确实为空”；空名单不得触发从全历史 summary/periodComparison 回填模型的旧兜底。
- 原始最后使用时间可缓存，过期判断随评估时刻刷新；没有新日志也必须正常退出。打开弹窗、用量刷新和在用覆盖率响应要使用一致时刻；后续新使用自动回归。
- 在线采用当前评估时刻；暂停冻结视图和静态导出采用对应快照的 asOf/生成时刻，离线重开不推进冻结快照。
- All Models 保留既有价目及已观测缺价记录，不删除手动费率、自动缓存或历史日志；自动发现调度沿用全历史来源集合，避免无关的发现行为变化。

验收：边界前后 1ms、恰好一个月、月底/闰年、未来或无效时间、重新出现、别名共享价目、多 harness、近月为空、无新增日志时过期均符合规则；在线和固定 asOf 的静态结果一致。当前真实数据没有过期模型这一现象是合法结果。

## 6. 重点风险与处理
