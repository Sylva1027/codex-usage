## R1. 衣服图标与相邻按钮保持相同可见度

对应用户第 1 项。

现状：`.skin-toggle svg` 使用 `currentColor`，但 `.theme-toggle` 的早期规则仍把 `color` 固定为 `#4b5563`；文/A 和日月图标则读取后置的 `--toggle-muted`／`--toggle-selected`。深色模式下，衣服描边因未接入共同色槽而显得更暗。

施工：给衣服外轮廓与中间横杠分别加稳定 class，例如 `.skin-icon-outline`、`.skin-icon-accent`。外轮廓读取与相邻按钮未选中部分一致的 `--toggle-muted`；普通状态的横杠也读同一色槽。完整保留 `.theme-toggle` 的共同按钮材质和尺寸，不靠降低图标 opacity 做弱化。

验收：浅／深模式中，衣服外轮廓的 computed stroke 与文/A 分隔符或未选中的日月图标使用同一颜色；按钮背景、阴影、圆角、宽高及位置继续与同组按钮一致。深色下无需悬停就能清楚看见衣服轮廓。

## R2. 中间横杠表达“已启用角色皮肤”

对应用户第 2 项。

**判定来自当前选中的皮肤，不来自弹窗打开状态。** `runtime.isCharacter(preference.skinId)` 为 true 时，横杠持续使用当前模式的主题强调色并带微弱荧光；`classic` 时回到普通描边且不持续发光。即使关闭弹窗、取消“显示角色”或把透明度设为 0%，只要所选仍是角色皮肤，横杠就继续表达该选择。

颜色与光效契约：

- 强调色取当前皮肤／当前模式已有的 `palette.tokens.accent`；未指定时沿用页面当前有效的 `--toggle-selected`／`--blue`。不能为十套皮肤额外填写品牌颜色。
- 页面强调色已经映射到共同变量时，直接复用 `--button-icon-glow`。若暂需按钮局部 accent，光效也用同一 accent，并沿用现有 `--button-glow-color` 的 **45% 混合、3px drop-shadow** 配方；避免横杠与光晕分别取两套颜色。
- 发光仅作用于横杠 path。外轮廓维持 R1 的中性色，SVG 整体不加持续滤镜，按钮框体不额外发光。
- 清理 `.skin-toggle[aria-expanded="true"]` 导致整件衣服变色／发光的规则。`aria-expanded` 继续只表达弹窗开关；悬停、聚焦的按钮交互效果沿用共同规范。
- 尽量用首屏脚本已有的根 `data-skin` 驱动选择状态，正常运行时由同一偏好状态维护；模式切换、皮肤切换、刷新恢复与简洁模式都必须同步颜色。`skin-bootstrap.js` 是生成物，如必须调整它，应修改生成来源并重跑准备／校验，而不是手改生成文件。

验收覆盖：简洁模式关闭／打开弹窗均无持续荧光；任一角色皮肤关闭／打开弹窗均保持荧光；切换模式更新 accent；隐藏角色及 0% 不误灭；刷新恢复角色后不等待打开弹窗才点亮；回到简洁模式立即熄灭。

## R3. 弹窗重新排成十款皮肤、五列两行

对应用户第 3 项，同时为第 5、7、8 项确定结构。

沿用 `.dialog-backdrop`、`.dialog`、`.dialog-heading` 与 `.dialog-actions` 的共同材质、标题、内边距、圆角和柔和投影。实际规则集中在 `styles.css` 后半段，不能另画一套浮窗外壳或复制早期已被覆盖的样式。

最终阅读顺序如下：

```text
模型角色皮肤                              [简洁模式]

显示角色 [开关]    角色透明度 [滑杆] 50%

┌──────────────── 一个连续的大凹槽 ────────────────┐
│ ChatGPT    Claude    GLM       Gemini    DeepSeek │
│ Kimi       Qwen      Grok      Muse      Mimo     │
└──────────────────────────────────────────────────┘
```

每张卡片内部保留名称、同时可见的浅色／深色预览、各模式色块或“配色待定”、选中标识。两套预览都常驻，打开弹窗和选卡不应轮流切换页面明暗。

`render()` 对 `runtime.getSelectableSkins()` 的结果按 `!skin.isClassic` 过滤，再按现有十角色顺序渲染。**只取消 Classic 的可见卡片，不删除注册表中的 classic，不改变默认值／存储 ID，也不把纯注册表测试的 11 项改成 10 项。** 删除仅用于 Classic 卡片的模板分支、排序和 CSS，前提是已核对没有其它调用。

桌面宽度 **≥1024px 固定五列、恰好两行**；1440×900、1280×800 和 1024×768 下，十卡及浅深对比、控制行、操作按钮无需纵向滚动即可查看。调整弹窗自身宽度、卡片留白和示意细节达成该目标，不能动后方看板。721—1023px 可降至三列，≤720px 可降至两列；窄屏允许弹窗内容区纵向滚动，操作区保持可访问，各卡浅深预览仍同时显示，不产生横向滚动。

不要继续保留当前 `max-width: 1024px` 的三列规则，也不要为了塞入无意义的第十一项而保留把预览压至 52／60px 的旧高度规则。先确定两行总高度，再在仍可辨识脸部的前提下调节细节；断点与具体数值通过实际截图确认。

## R4. 透明度滑杆与项目材质、主题色一致

对应用户第 4 项。

控制行置于大凹槽之外，与标题／操作区保持共同节奏。标签与百分比正常排版，不给“角色透明度”几个字或整段 label 单独套一个输入框式凹陷。凹陷应明确属于**滑杆轨道本身**。

仅针对 `#skinOpacity[type="range"]` 重置从通用 input 规则继承的整块背景、边框、padding 和 box-shadow，再分别绘制轨道／滑块。保留原生 range 的语义与键盘操作，补齐 `::-webkit-slider-runnable-track`／`::-webkit-slider-thumb` 和对应 Firefox 伪元素。

- 轨道使用 `--ceramic-well`／`--track` 与轻量 `--neo-inset-small`，胶囊形，建议起始厚度 6—8px。
- 已填充段使用 R2 同源的当前模式有效 accent；未填充段使用槽底色，不使用浏览器默认蓝色或硬编码颜色。
- 滑块使用共同陶瓷渐变、边缘和 `--neo-raised-small`，建议起始直径 14—16px。主题色可用于滑块细节；聚焦圈与其它控件一致。
- 若采用渐变表示进度，以统一更新函数写入百分比 CSS 变量；初次打开、刷新恢复、拖动及程序化修改都调用它。不要只在 `input` 事件更新颜色而导致初始填充长度错误。

保留 0—100、步长 1、实时百分比、立即应用与持久化。新用户默认 50%；已有 0%、35% 等偏好原样恢复。删除恢复按钮不等于删除默认 50% 或强制把已有设置改回 50%。

## R5. 十张卡片置于一个大凹槽

对应用户第 5 项。

给网格增加一个连续容器，例如 `.skin-gallery-well` 包裹 `#skinGrid`。容器使用共同 `--ceramic-well`、`--neo-inset` 与项目已有的圆润边缘；两行共享同一个槽底，没有逐行分割或第二个无意义的槽框。

小卡片在槽底上使用共同陶瓷表面与轻量凸起阴影。名称、浅深预览、配色说明整齐对齐，不给每块文字再套输入框式小凹槽。选中状态以主题色边缘／文字或小标识清楚表达，可复用现有按下态，避免给整张卡片加过强的发光框。

施工起点可用槽内 padding 12—16px、卡间 gap 12px，再按共同 spacing 和实际五列效果收敛；这些是弹窗内部参考值，不是主页面布局变更。统一卡片最小高度，空配色状态也不导致十卡参差。浅深预览及配色色块按模式分组，不将两套颜色混在一排无法辨别的色块里。

验收：浅／深模式均能看出“弹窗外壳 → 一个大凹槽 → 十张小卡片”的层级，槽底在两行间连续，阴影方向和其它弹窗／主页面一致。

## R6. 缩略图向右构图，优先露出脸部与躯干

对应用户第 6 项。用户提供的失败构图参见 [参考截图](assets/2026-10-02-skin-dialog-feedback-reference.png)：示意框体占据左侧及中部，角色居中后主体被遮挡。该图是问题示例，不能照着作为目标。

现状：`.skin-preview-art` 用 `left: 50%`、`translateX(-50%)`、`height: 100%` 居中塞下整个人物；`.skin-preview-ui` 又占左侧 62%／56%／60%，还带模糊背景。需要改变空间安排，而不只是把示意面板调得更透明。

施工原则：**示意界面占左侧，人物脸部及躯干占右侧；全身完整性让位于辨识度。**

- 先为每个浅／深预览明确人物舞台和左侧示意区。示意界面建议先控制在宽度 40—45% 内，保留少量标题、文字、按钮及图表即可。
- 人物锚点向右调整，脸部／躯干中心建议从舞台宽度的 72—80% 开始。实际参数以有效线稿位置为准，不能把图片透明画布中心当作脸部中心。
- 允许放大上半身、裁掉裙摆或尾巴，人物高度可先试舞台高度的 1.7—2.2 倍并按头顶定位，再逐角色检查；禁止只把完整全身缩得很小来机械容纳。
- 角色轮廓可以突破内部示意框体的视觉边缘，在右侧显示一部分；所属浅／深舞台承担最终裁切和隔离。不得跨到相邻模式、邻卡、名称、控制行或操作按钮上。
- 示意面板、柱状图与模糊层不得覆盖脸部和主要躯干。必要时调其位置／宽度或去掉会模糊人物的 backdrop-filter，不能靠把人物放到所有示意内容上方覆盖配色信息解决。
- 保留原透明线稿、对应浅／深素材及固定 50% 的比较透明度；用户调整主页面透明度不影响缩略图比较。

在 `skin-picker.js` 内建立仅用于缩略图的构图参数，例如 `previewComposition[skinId] = { faceAnchorX, topOffset, scale }`，经局部 CSS 变量应用。先用统一起点，再为真正需要的角色单独校正；同一角色浅／深构图尽量一致。**不修改 `skins.js` 中已测量的页面立绘 `skinDisplayParams` 来修缩略图。**

验收不是“向右移了若干 px”，而是十角色 × 两模式共 20 个预览中，脸部和主干均可见且不被示意 UI 遮挡；必须逐张视觉检查，并保存总览及局部截图。具体锚点数值属于实施时校准结果，不能把以上起始值当成已验收值。

## 1. 配色预留空间与局部隔离

本轮重排不改变用户后续填色入口 `public/skin-palettes.js`。未填仍为 null，只能显示对应模式的现有基底与“配色待定”，不能把现有页面颜色标成角色正式配色。

现有 picker 的 `COLOUR_TOKENS`／`TOKEN_TO_CSS` 与注册表字段存在差异，例如 picker 读取 `text`／`mutedText`／`border`，注册表提供 `textPrimary`／`textSecondary`／`panelBorder`；`chartSeries` 也在 palette 的独立字段内。改写卡片时应统一按注册表真实字段映射到预览变量，保留用户填色空间，不另建一套字段。用隔离 fixture 检查文字、边缘、强调色、控件与系列色，而不仅检查 pageBackground。

只读取目标皮肤、目标模式的已指定值；局部浅深作用域与其它卡片互不污染。R2／R4 的实际控件主题色则读取**当前已选皮肤、当前页面模式**，不可误读正在预览但未选中的卡片。完整的全页配色联动仍属于用户提供真实颜色后的既定工作，本轮不扩展为全页配色重构。

## 2. 执行顺序与文件联动

## 5. 后续新增需求：主页面两侧脸部随留白居中（仅记录）
