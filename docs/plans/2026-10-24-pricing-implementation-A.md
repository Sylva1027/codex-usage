## 1. 做什么，以及谁写什么

A 负责现有页面里的费用说明、缺价模型编辑、线路编辑、来源与重试状态，以及这些交互的测试。保留现有布局和编辑器，不做界面重构、通用表单框架或新增展示分组。

- **A 独写：** `public/app.js`、`public/app-state.js`、`public/index.html`、`public/i18n.js`、必要的 `public/styles.css`；`test/app-render.test.js`、`test/i18n.test.js`。只有实际受影响才改相邻的 app/timeline 测试；新增交互测试可集中在 `test/pricing-editor.test.js`，不按卡建文件。
- **B 内核 worker 独写：** `public/pricing-models.js`、`src/pricing.js`、`src/pricing-auto.js` 及其测试。虽然 resolver 在 public 目录，A 也只调用，不复制、不改。
- **B 存储 worker 独写：** `src/pricing-store.js`、`src/server.js` 及其定价 API 测试。
- **Codex 主审整合：** 必要的 usage 投影、缓存、冷热/冻结及文档接线。A 不改数据库、归档、perf、CLI 或真实价目文件，不接网关账本。

以上是本项目内的预定归属，**不是解除其他施工线的锁**。历史保留计划当前记录 public 冻结，且仓库有大量未提交工作。启动时先由主审核对[历史保留文件锁](2026-10-22-history-retention-implementation-plan.md) §3 和 TPS 的实际占用；未释放时，可在包含当前工作基线的隔离副本准备 A，不能覆盖共享目录。不要直接从旧 HEAD 建副本而丢掉当前未提交依赖，也不要全仓 reset、格式化或提交无关文件。

## 2. 外部监工的执行方式

每次派一张卡，目标 **15–20 分钟，包含定向验证和交接**。这是粒度，不是到点宣称完成：15 分钟有阻碍就报告已改文件、具体失败和剩余步骤；预计超过 20 分钟时，把未完成行为拆成一张明确后继卡，不静默拖成长尾。不要把一次运行较慢的全仓测试算成所有卡的必做工作。

同一个 A 执行者顺序处理共享 UI 文件即可，不需要为了并行再拆组件。外部监工核查本卡的行为和 diff 后可释放 A 的本地后继；跨 A/B 的真实接通由 Codex 主审确认。接口尚未实现时可以用测试夹具完成开发，但报告必须写“夹具通过，联调待验”。

优先复用 `pricingContextsHtml`、`writePricingField`、`modelPricingInputsChanged`、现有弹窗、`escapeHtml`、i18n 和测试夹具。不要在浏览器再实现费率选择、来源优先级或自动发现。

## 3. A/B 共用的页面/API 契约

**本节是 A/B 交接字段的唯一约定。** 都是拟实现接口，不代表当前服务已经支持。若源码变化使某一字段确需调整，Codex 主审先同步本节及相应测试；不要让两个实现各自兼容多个猜测版本。

### 3.1 费用与覆盖

- 沿用查询返回的 `costEstimate`、`totals.total` 和现有币种字段，不从模型条目数推算 token 覆盖率。
- 第一批 `costEstimate.priceMode = "minimum-fallback-scenario"`：保留金额算法，注明“包含最低费率假设”。第二批改为 `"priced-only-scenario"`：缺费率不补价，标题显示“已定价部分合计”。
- `minimumEstimatedTokens` 是 `pricedTokens` 的子集；`unpricedTokens` 是另一部分。用当前查询的 `totals.total` 作分母，不把服务等级、上下文、缓存写入等重叠诊断相加。空范围不显示 NaN/无穷比例。
- 第二批取消的是“缺价借全局最低费率”，不是删除已有的模型内未知明细情景；因此第二批的 `minimumEstimatedTokens` 仍可能大于零，需按原因解释。
- 无可定价部分显示“— / 未定价”，明确免费仍显示 0；混合币种仍按现有汇率展示。所有视图提示 API 等价估算、历史按当前有效价目回算。
- `usageCoverage` 继续用于模型名匹配清单，不能冒充当前查询 token 覆盖率；自动价是否匹配、费率是否手动覆盖、线路身份是否确认分别说明。

### 3.2 读取与保存

`GET /api/pricing` 保留现有 `version / checkedAt / usdToCnyRate / models / automatic / usageCoverage / modelActivity`。第一批增加实时编辑用 `editVersion`；页面打开草稿时一并保存，PUT 原样回传。它还检测有效价格相同但手动覆盖层变化的冲突，不能用费用 `version` 替代。冻结读取不提供实时 `editVersion`。第二批添加有效 `routes`，无线路时为 `{}`。第一批起额外返回 `manualOverrides`，形状为 `{ models: <稀疏字段覆盖>, routes: <稀疏字段覆盖> }`，只供识别手动字段；页面不把它当完整价目。

联调补齐的明确元数据：`manualOnlyEntries: { models: [key], routes: [key] }` 由服务端实际无自动/内置底值计算，用于识别可移除的手动条目，不能凭覆盖层恰好填满费率就推断“无底值”。`capabilities: { routeEditing: boolean, rowRefresh: boolean }` 只表示这两个已约定功能是否真实接通；当前过渡期为 false，分别在 D07、D11 验收接通后启用。页面未得到 true 时保留只读线路展示、普通模型手动纠正和全局刷新，不开放伪线路写入或伪单模型刷新。

复用 `PUT /api/pricing` 全目录编辑协议，不另建 CRUD 服务：

```json
{
  "version": "编辑打开时取得的版本",
  "editVersion": "编辑打开时取得的实时编辑版本",
  "checkedAt": "2026-10-24",
  "usdToCnyRate": 6.72,
  "models": {},
  "routes": {},
  "restoreAutomaticExchangeRate": false,
  "restoreFields": [
    { "scope": "model", "key": "example-model", "path": "short.input" }
  ]
}
```

上面 `models: {}`、`routes: {}` 只是结构示意，**不是可直接提交的完整载荷**：models 仍带齐当前内置及自定义条目，routes 带齐已有线路。第一批可省略 routes；第二批服务端对旧客户端省略 routes 按“保持原线路”处理，显式空对象才是提交空线路目录。

- `restoreFields` 可省略；scope 为 `model / route`，path 只接受经校验的既有价目字段路径，不接受任意对象路径。撤销是删除该手动覆盖，再读取保存时最新有效自动/内置值，不把旧自动值重新写成手动值。
- 页面把撤销显示成“待保存：恢复自动/内置值”，不必为预览另下载整份自动目录。同一字段不能同时编辑和撤销；用户重新编辑则清除其待撤销标记。
- 没有自动/内置底值的必需字段不可单独撤销成缺损价目；提示移除整个手动条目，或补齐有效值。移除自定义条目通过目录中省略该条目表达，不能移除内置模型。
- 未改字段不得因提交整份目录变成手动覆盖；已有手动字段即使恰好与自动值相等也保持覆盖，直到显式撤销。这个合并逻辑由 B 实现。
- 成功返回新的有效目录，页面重新获取状态并重算用量；取消不发保存请求，400/409/写盘失败保留草稿并说明错误。409 提示重开/重新核对，不能自动覆盖新版。
- 有 `editVersion` 时服务端优先且只校验它；旧费用版本不能绕过编辑冲突。旧服务未返回该字段时继续使用原 `version` 兼容路径，不在页面自行生成版本。
- frozen 读取仍用现有 `?snapshot=`；保存只改实时价目。冻结视图的费用、目录和版本不能随保存变化；实时自动刷新状态可另标“当前服务状态”。

### 3.3 目录条目与解析

普通模型仍放在 `models`，不允许把 `seller/model` 塞进去。线路放 `routes`，首版只给原始模型名已携带可靠、完整线路键的记录使用。

```json
{
  "seller-a/example-model": {
    "canonical": "example-model",
    "currency": "USD",
    "short": { "input": 1, "cachedInput": 0.1, "cacheWrite": 1.2, "output": 3 },
    "long": { "input": 1, "cachedInput": 0.1, "cacheWrite": 1.2, "output": 3 }
  }
}
```

这是**合成测试价格**，不代表任何供应商报价。四项单位均为对应币种/百万 tokens；0 必须是用户明确输入，空白不能 `Number("")` 变 0。新条目必须提供适用档位的完整必需费率：同价长短档可经明确确认复制；分档则填实际阈值及完整两档。缺少档位政策不能由校验器默默补齐，Fast 不默认 ×2，峰谷也不自动继承。

K01 已确定：后端对新条目可归一化出 `allowFastFallback:false`，表示无明确 Fast 费率时不推导。编辑器保留此策略字段，不另加开关，也不把它变成 `fast:null`；后续明确 Fast 费率仍可生效。未定价原因 `fast-pricing-unavailable-unpriced-scenario` 用“缺少 Fast 费率，相关部分未定价”解释。

`canonical` 只说明模型归属，不自动继承模型费率、Fast 或峰谷政策，也不证明卖家身份。来源 URL 可选，`source` 仍只接受 HTTP(S)；“手动”由覆盖层标识。模型最多256条，模型名/canonical为1–80位合法标识；线路单独上限512、键长1–160。主审代表性容量实测后，价目PUT上限定为256 KiB；冲突、非法键、载荷超限显示服务端错误并保留草稿，不截断。

B 将共用 resolver 扩展为 `resolvePricingModel(rawModel, models, routes = {})`。原模型返回值不变；精确线路返回 `{ rawModel, catalogKey: <线路键>, matchType: "route" }`。A 据此选择 models 或 routes 的条目；不自己剥前缀匹配 canonical，也不改变已有免费规则优先级。

新增/移除目标时替换 models/routes 对象，不原地改变其键集合；共用 resolver 的索引缓存依赖目录对象身份。普通费率编辑继续复用现有草稿流程，无需另建缓存失效机制。

### 3.4 刷新、来源与重试

`automatic` 沿用现有时间、`issues`、`modelMetadata`、`priceSourceCoverage`、汇率字段；B 新增：

- `pricePartialFailure: boolean`，以及 `exchangeRateOrigin: "manual" | "automatic" | "built-in"`。价格与汇率的结果分开；报价年龄取 `exchangeRateDate`，尝试时间不是成功时间。
- `discoveryResults[]` 保留 model/status/reason，增加 `retryable: boolean`、`nextRetryAt: ISO时间 | null`、`retryAfterCapabilityChange: boolean`。nextRetryAt 表示最早可再次尝试的时间；第三批后台调度未交付时，不把它写成保证自动执行的时间。页面按后端结果显示原因和重试安排，不自行硬编码。旧响应缺字段显示“重试安排未知”。

第一批无能力变化的 unsupported-provider 等拒绝不再提供无意义的行内“强制全量匹配”；保留手动纠正入口及全局“刷新全部价目”。网络问题仍可恢复，解析能力或明确映射变化后可重新评估。第一批若行级接口尚未交付，可显示原因及既有重试安排，不伪装成单模型请求。

行级能力尚未接通时，服务端对带 `body.model` 的请求明确拒绝为 `ROW_REFRESH_UNAVAILABLE`，不忽略目标后转为全局刷新；普通无 model 的全局请求保持原协议。

第四批行级操作为 `POST /api/pricing/refresh`，body `{ "model": "<完整原始名>", "force": false }`；B 只处理该目标、复用可用目录缓存，且不刷新无关来源或汇率。全局操作保留 `{ "force": true }`。响应仍使用现有 catalog/automatic/discovery 形状，A 不增第二套状态。

后台调度是设计方案第三批，可独立交付，不是 A 的来源说明卡的依赖。未交付前，不写“关闭页面也会自动刷新”。
