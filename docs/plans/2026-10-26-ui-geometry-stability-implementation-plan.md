# UI 几何稳定性 Implementation Plan：双 worker

更新：2026-10-26。状态：**15 张施工任务卡与 UI 专项验收完成；G3 已执行，报告字段契约失败已修复并通过定向回归**。实际结果与边界见[施工验收](../validation/2026-10-26-ui-geometry-stability.md)。本文件负责施工拆分、依赖和进度；[主方案](2026-10-25-ui-geometry-stability-plan.md)负责设计要求及技术依据。旧 `output/geom-probe/new-section-5.md` 仅作历史参考。

配置：**1 名主审协调，2 名 worker 并行；15 张任务卡**。B5 在施工中拆为 B5a 正常矩阵与 B5b 状态/字体续卡，原验收项全部保留。A 负责几何 CSS，B 负责结构、文案、生产样板和测试。用户指定所有 worker 必须显式使用 **DeepSeek Routing Group（`group/deepseek`）**；无法指定或创建失败则停止，不回退其他模型。

## 1. 执行约定

- 一卡交付一个完整界面区域或一组共享基础规则，包含该改动必需的调用点、翻译及定向验证；不按单个选择器、单句文案拆卡，也不把全站 CSS 或全部弹窗交成一张大卡。
- **每次只派一张已就绪卡，交付后再续派下一张。** 不把 A1–A7 或 B1–B7 整条队列作为一次任务交给 worker。续派只携带当前卡与必要的上一卡交接。
- 卡内通常只涉及少量紧密相关文件。发现第二个独立目标时，由主审拆一张同 owner 的续卡并更新依赖；不在原卡里悄悄扩成全站重构。
- worker 首次只读本节、自己的文件边界和任务卡、主方案 §0 / §1.1 及对应区域小节，再读相关代码与调用方；无需每卡重读全部历史审计和临时探针。
- **常驻说明约束立即生效。** 默认删除、合并无当前操作用途的说明；系统机制、估算口径和边界解释默认主动展开。费用估算框内既有详情按用户明确要求直接展示，不加折叠入口。不为每段被删除的说明补徽标、问号或新容器。
- 清理对象包括说明性徽标与重复提示；同时保持操作按钮、表单标签、数值与单位、可访问名称和必要的表单校验语义。不得借维护这些语义之名恢复说明墙。
- 保持陶瓷拟物、既有光源、颜色和角色语言；不改 `.main-grid` 列结构，不做手机适配，不给文字设置统一字数上限，不用自动缩字号迁就布局。
- 不改 `src/**` 的计费、来源、汇总、存储或 API 语义，不增加产品选项、构建步骤或运行依赖。
- 正式几何回归测试在 token、生产样板及**对应区域**整理完成后写入。早期卡使用局部浏览器测量与现有功能测试，后期允许已完成的主页面先进入测试，弹窗继续施工。

- A 的滚动交付记录：`output/ui-geometry-implementation/A-report.md`。

### B 的写入范围

- `public/index.html`、`public/app.js`、`public/i18n.js`；实际涉及其文案时才修改 `public/history-archives-ui.js`、`public/skin-picker.js` 或 `public/skin-ui.js`。
- 新增 `docs/panel-anatomy.html`，以及相关既有前端测试、后期的 `test/ui-geometry.test.js`。
- B5 确有必要时增加一个本轮 fixture 辅助文件；默认先复用现有 fixture，不改共享 fixture 的原有语义来迁就新界面。
- B 的滚动交付记录：`output/ui-geometry-implementation/B-report.md`。

### 主审的范围与职责

- 施工中 B5 准备范围扩散且拆小后仍未产出测试文件，已停止原 B，B5a / B5b 的 `test/ui-geometry.test.js` 写入权交给主审，避免阻塞后续；其他文件继续原 owner，后续回归分派须重新明确单写边界。未创建其他模型的代理。
- 主审维护本实施计划、主方案和文档导航，接收每卡结果，组织整合快照及最终验收。
- 开工时记录本轮起点和已有重叠改动；接入 worker 产物时保留已有工作。每个目标文件同一时刻只有其 owner 写入；其他工程也在修改共享文件时，由主审协调写入时段，不覆盖其最新修改。
- B 需要 CSS 改动时交给 A：给出选择器、目标关系和对应 DOM；A 需要结构改动时同样交给 B。接收方将必需的小调整纳入当前相关卡，不为每次交接另开任务。
- DOM 的 id、事件选择器、表单 name、ARIA 关联及详情入口优先保持；确需调整时，B 同卡修齐调用方和定向测试，并通知 A。
- A1 后共享 token 命名保持稳定。主页面在 A4 / B4 后冻结其共享规则；弹窗后续改动尽量限定在对应弹窗内。确需回改时点名受影响卡，仅重验相关区域。
- 测量和截图针对已经整合、没有进行中写入的区域；最终整页验收使用稳定快照，不拿两个未整合的 worker 截图证明整体完成。

每卡交付只需写清：**完成目标、实际改动、验证命令或截图、剩余问题与依赖交接**。各 worker 只更新自己的滚动报告；任务状态只由主审在本文件更新，避免多份账本漂移。

任务状态使用 `TODO / DOING / DONE`；主审核对本卡验收后标记 DONE 并释放依赖，不要求每卡重跑整页矩阵或完整工程检查。

## 3. 队列与依赖

下面是预计并行队列，**不是七个全局等待屏障**。前一张卡交付后，只要下一卡的明确依赖完成，就立即继续。

1. A1 共享 token 与代表组件接入 ∥ B1 生产样板与文案处置清单。
2. A2 顶栏与工具栏几何 ∥ B2 主页面说明清理及死代码移除。
3. A3 指标卡与对比条几何 ∥ B3 数据来源、皮肤弹窗结构与文案。
4. A4 内容面板、表格与历史区域几何 ∥ B4 计价弹窗结构与文案。
5. A5 数据来源、皮肤弹窗几何 ∥ B5a 主页面正常矩阵。
6. A6 计价及模型计价弹窗几何 ∥ B5b 状态/字体续卡；B5b 与 A5 完成后即续派 B6，不额外等待 A6。
7. A7 整页视觉一致性复核与定点修复 ∥ B7 计价弹窗回归与交互收口。

只设三个整合检查点：

- **G1：A1 + B1。** token 已在生产代表组件使用，样板复用生产样式，尺寸和文案原则可供后续卡直接沿用。
- **G2：A4 + B4。** 主页面完成对应整理，四个弹窗的结构与文案就绪；开始对已完成区域落正式几何测试。A5 / A6 继续处理弹窗 CSS。
- **G3：A7 + B7。** 全部实现与对应回归整合，主审执行最终整页对照和一次工程检查。

某一张卡返工，只阻塞依赖它的任务。对方可以继续已具备条件的卡；不把整条双 worker 队列停下来等一次局部修改。
