## 1. 范围与参与清单

用户明确：**主界面每一个框体均参与 SpotlightCard，凹陷区域不参与**。12 张指标卡只是其中一部分，不是数量上限；不得把 `.panel`、`.comparison-item` 留到另一个推广计划。

- 纳入主界面的全部非凹陷框体，包括指标卡、趋势对比卡、时间分布／详情／跨时间对比／数据来源／费用说明等外层面板，以及其它实际呈现为非凹陷框体的工具栏或控件表面。是否参与以现有表面形态为准，不能只按某个类名或固定数量判断；无独立表面的纯布局容器不制造新框体。
- 明确排除详情 `.bar-track` 长条槽及其填充内容、搜索框和其它输入凹槽、指标卡／对比卡数字凹槽、图表凹槽、对比表格凹槽、来源列表凹槽、说明凹槽、分段选择轨道等所有凹陷表面。排除既指不生成自己的光效，也指不被祖先框体的聚光层照亮。
- 实施前对当前主界面静态 DOM、动态渲染模板及最终 CSS 做参与／排除清单，记录选择器、表面形态、嵌套关系、伪元素和层级冲突。现有可供核对的锚点包括 `.metric`、`.comparison-item`、`.panel`、`.toolbar`；凹陷锚点包括 `.metric strong`、`.comparison-item > strong`、`.bar-track`、`.timeline-chart-well`、`.comparison-table-frame`、`.home-list`、`.cost-estimate-note`、`.segmented-well` 及搜索／输入控件。这是核对入口，不是完整清单，也不授权把 `.toolbar` 中无独立表面的部分做成新框体。
- 控件按当前状态核对：若按下／选中后采用凹陷表面，该状态停止自身光效并保持原有内凹效果；非凹陷子框体与父框体分别按自身边界处理，不使嵌套光层累加到失真。
- 本阶段范围为主界面；不据此扩大到独立弹窗或皮肤缩略图。保持现有按钮反馈、人物构图及所有功能框体尺寸、位置、排布。

## 3. CSS 接入与凹陷保护

旧版仅针对 `.metric::before` 的片段不能直接推广。先完成 §1 清单，再为参与框体建立统一接入标记／选择器与明确的凹陷排除规则；以源码锚点定位，不依赖旧行号。

1. 每个参与框体拥有相对其边界的 `--spotlight-x`／`--spotlight-y` 和径向聚光层；颜色引用 `var(--skin-active-accent, var(--blue))`，强度保留统一调节点。只有支持 hover／fine pointer 的输入状态显示，装饰层不得接收点击。
2. 光层位于框体既有背景之上、文字／数字／图表／控件内容之下。逐类核对现有定位、堆叠上下文与 `::before`／`::after`，不可一律占用伪元素或设置 `z-index: -1` 并声称所有框体层级都成立。
3. 光层按宿主圆角裁切，同时保留宿主外阴影、菜单浮层、tooltip、焦点轮廓和 New 徽标。不能给所有父框体直接追加 `overflow: hidden` 而裁掉可交互子内容；按框体选择装饰层自身裁切或其它经验证方案。
4. 凹陷区域保留自身既有背景、内阴影、圆角、图表和条槽颜色，不绘制光层。**只跳过凹槽事件不够**：祖先框体的光层也不得透入凹槽。实施时核对凹槽背景是否不透明并位于祖先光层之上；有透明表面时采用有效的排除遮罩／分层，不为省事改变原有凹槽颜色。对含透明部分的 `.bar-track` 等必须实测。
5. 指针进入凹陷后，关闭该位置对应的祖先／子框体聚光，离开后恢复；不得留下上一位置高亮。嵌套非凹陷框体需明确命中与层级，避免光层在同一表面重复叠加。
6. 不给装饰框体添加 tabindex，不改功能焦点顺序；已有可聚焦控件可沿用 focus-within 反馈，但必须遵守凹陷状态排除及层级要求。

## 4. JS 事件与动态框体

旧版只在两个 `.metrics` 上委托、只寻找 `.metric` 的监听已不适用。

- 使用覆盖主界面的独立事件委托（例如 `.shell` 根节点），匹配 §1 清单中的全部参与框体；不要混入已有 tooltip 的 document pointermove。支持动态生成或替换的 `.comparison-item` 等目标，不逐项重新绑监听。
- 按事件实际命中先判断凹陷排除区域／当前凹陷控件状态；命中排除区时清除正在显示的聚光，不能简单 return 后留下祖先的 hover 光层。命中非凹陷框体时按约定的嵌套命中策略计算位置，避免祖先和子框体无意叠加。
- CSS 与 JS 使用同一 hover／fine pointer 条件；事件发生时读取 `MediaQueryList.matches`，额外忽略 touch。能力变化、pointerleave／cancel、目标移除或失去可见性时清理激活状态，混合设备切换不得残留高亮。
- 坐标相对命中框体的 `getBoundingClientRect()`，覆盖页面与内部滚动、窗口变化、动态内容展开／重建。实测大面板及动态区域的性能；必要时按动画帧合并，位置缓存须处理所有布局失效，不能仅在进入时缓存。
- 主界面原有点击、拖动、文本选择、搜索、图表 tooltip、菜单与滚动均保持可用。主界面之外不激活该效果。

## 5. reduced-motion 取舍（本轮采用 A）

- **A（已接入）**：在 `prefers-reduced-motion: reduce` 下保留符合输入条件的聚光跟随，关闭聚光渐显过渡。普通模式渐显 120ms；退出和进入凹陷立即清除。
- **B（保留为可选替代，未采用）**：reduce 下完全关闭聚光，JS 同步跳过坐标更新并清理已有激活状态。

选择应用于全部参与框体，不能只给 `.metric` 降级。原有控件减少动态效果策略保持。实施验收显式覆盖 reduce／no-preference，不以本机默认状态替代两态验证。
