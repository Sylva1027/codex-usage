# Claude 价格与现有来源计费接入计划

日期：2026-10-01，更新：2026-10-02。状态：实施与验收已完成，纳入皮肤系统实施前的[本地保存点提交](../validation/2026-10-02-pre-skin-checkpoint.md)，未发布新版本。逐项进度见 [TODOs](2026-10-01-claude-pricing-todos.md)，结果与边界见[验收记录](../validation/2026-10-01-claude-pricing/README.md)。

## 已确认范围

用户选择先补 Claude 价格和现有来源计费。目标是让 OpenCode、ZCode 等已有来源中出现的 Claude 模型使用可核验价目估算费用。

费用沿用项目的 API 等价估算口径。通过中转调用时，可以用现有手动覆盖填写实际费率；中转模型名称只有在映射关系已确认时才关联官方模型。Claude Code 本地日志接入另行规划。

## 规划时的代码与缺口（实施前）

- `src/pricing.js` 当前有 86 个内置模型，Claude 条目为 0；已有输入、缓存读取、缓存写入、输出四类单价，以及 Standard/Fast 与请求上下文档位。
- `src/pricing-auto.js` 的来源域名与提供商映射缺少 Anthropic。Models.dev 支持按提供商和精确模型键更新已有 USD 条目，适合复用。
- LiteLLM 备用价格解析与新模型发现目前面向 OpenAI。不能直接把 Claude 送进 `parseOpenAIModelPricing()`；该函数还可能推导 Fast 倍率。
- `public/pricing-models.js` 已有前后端共用解析器、明确别名和最长边界前缀匹配。Claude 新旧版本需各自建价，不能靠一个宽泛的 `claude-sonnet` 或 `claude-opus` 条目匹配所有版本。
- OpenCode v2 已把并列的输入、缓存读、缓存写重构为总输入。ZCode 当前直接采用数据库的 `input_tokens`，其 Claude 行的上游语义尚未核验；DSH 非零缓存写入也是已有待核实项。
- 模型上限在 `src/pricing.js`、`src/pricing-store.js` 和界面提示中分别出现，当前为 100；保存请求体上限为 128 KiB。
- 历史费用按当前活动价目重算，因此补价后已有记录也应更新，无需修改原始日志。

以上为实施前源码观察；完成后的现行规则维护在[计价说明](../11-pricing.md)，实际结果维护在验收记录。

## 定价与模型范围

以 [Anthropic 官方价格页](https://platform.claude.com/docs/en/about-claude/pricing)为人工核验依据，所有单价采用 USD / 百万 tokens。记录来源和核验日期，实施时重新核对。

建议首批覆盖官方价目中的 17 个普通模型版本：

- Opus：5.5、5、4.8、4.7、4.6、4.5、4.1、4。
- Sonnet：5.5、5、4.6、4.5、4。
- Haiku：4.5、3.5。
- Fable：5.1、5。

这会把内置目录从 86 项增加到 103 项。已退役版本仍可保留用于已有记录的等价估算，并在说明中区分历史用途。更早版本和受限模型在确实出现用量后再补，不能套用相邻版本的价格。

当前官方样例：Sonnet 5.5 的输入/输出为 $2/$10，Opus 5.5 为 $4/$20，Haiku 4.5 为 $1/$5，每百万 tokens。这里是带日期的核验样例，正式有效价目维护在代码和自动缓存中。

缓存写入区分 5 分钟与 1 小时，分别为基础输入价的 1.25 倍和 2 倍。缓存读取费率逐模型记录：例如 Opus 5.5 为 $0.20/百万 tokens，不能统一按输入价的 10% 推导。以上来自官方价格页。

## 建议实施顺序

### M0：锁定已有来源的字段语义

先用现有适配器的版本文档、上游写入逻辑或脱敏样本确认字段含义，再决定是否修改适配器。

- OpenCode v2：复用已存在的总输入重构，补 Claude 非零缓存写入与费用断言。
- ZCode：核对 Claude 行的 `input_tokens` 是总输入还是非缓存输入；不能仅按模型名无条件加上缓存读写。
- DSH：核对其非零 `cacheWriteTokens` 是否已包含在原始输入中；该问题目前是待核实，不预先认定必须修复。
- 每个来源分别核对输出是否已包含推理 tokens，保持总输出只收费一次。

Anthropic 原始 API 的三个输入字段为并列计数：总输入 = `input_tokens + cache_read_input_tokens + cache_creation_input_tokens`，见[缓存用量说明](https://platform.claude.com/docs/en/build-with-claude/prompt-caching#how-do-i-calculate-total-input-tokens-from-the-usage-fields)。这个公式只适用于确认仍保留原始语义的来源。

项目标准事件继续保持：`usage.input` 为总输入，`usage.cached` 和 `cacheWriteTokens` 为它的子集，`usage.total = usage.input + usage.output`。计费把输入拆成普通输入、缓存读、缓存写，再加总输出。

### M1：内置价目、容量与模型匹配

- 在 `src/pricing.js` 添加独立 Claude 价目，明确 USD、Anthropic 来源和逐模型四类费率。
- 将模型上限统一为一个共享常量，建议提升至 256；同步校验、自动发现容量和界面文案。容量错误应能与“缺少内置模型”错误区分。
- 检查保存较大目录时的序列化体积；如 128 KiB 无法容纳受支持的配置，再同步调整请求体限制并验证超限拒绝。
- 在共享模型解析器中支持官方别名与已确认的日期快照。4.6 及之后的无日期 ID 是固定版本，应保留独立价目；规则依据见[官方模型 ID 说明](https://platform.claude.com/docs/en/about-claude/models/model-ids-and-versions)。
- 保留精确键优先和免费规则。增加防串价回归：未收录的 `claude-sonnet-4-9` 不能被 `claude-sonnet-4` 前缀借价；已确认的日期后缀可映射。
- `anthropic/` 等路由前缀只在来源已确认是相同计价口径时规范化。Bedrock、Vertex 和未经核实的中转别名保留来源或手动配置，不直接等同于官方账单。
- Claude 4.6 及之后的官方标准价不因长上下文提高；较旧版本的历史长上下文政策单独核验，不继承 OpenAI 的 272K 规则。

验收：断网也能识别首批 Claude 版本；旧配置加载后包含新增内置项；旧模型手动覆盖保持生效；新增版本不会被旧版本前缀误匹配。

### M2：已有 Claude 价格的自动更新

- 为 Anthropic 官方域名增加明确的 `anthropic` 提供商映射，复用 Models.dev 已有 USD 更新流程。
- 内部目录键与上游日期快照键不同时，维护有证据的对应关系；更新必须在 `anthropic` 提供商下匹配确切模型，不能搜索其他厂商同名条目。
- 核对上游缓存写入字段的 TTL 口径。不能把 1 小时价格写进现有 5 分钟 `cacheWrite` 字段，也不能把缺失字段当成 0。
- 复用内置值 → 自动缓存 → 手动字段覆盖的优先级，以及失败保留旧价、24 小时刷新、1 小时失败冷却。
- 当前批次先维护已收录 Claude 条目。未知 Claude 模型继续保留缺价提示和手动新增入口；完整的 Claude 新模型自动发现另行扩展。
- 首版无需增加独立的官方网页抓取器。官方价格用于核验内置值，Models.dev 用于已支持字段的自动维护；若两者有实质冲突，记录差异后决定字段是否适合自动覆盖。

验收：同名其他提供商不串价，部分字段缺失不抹掉内置值，失败保留缓存，手动改价不被自动刷新覆盖。

### M3：现有来源计费、界面与历史一致性

- 根据 M0 的证据修改必要的来源映射；已满足标准事件口径的适配器直接复用。
- 在 `public/app.js` 的价格来源标签中增加 Anthropic，沿用“在用模型/全部模型”、共享编辑和 USD/CNY 展示。
- 首版现有单一 `cacheWrite` 费率明确采用 5 分钟标准场景。来源无法提供 TTL 时，非零缓存写入须提示 TTL 未确认，不能宣称已按真实 TTL 精确计费。
- 若来源明确保留 1 小时或混合 TTL 明细，须在对该情况宣称支持前扩展费率、事件字段、持久化和编辑 UI；首版不能静默按 5 分钟结算这类已知记录。
- Fast 仅在官方有对应模型价目且事件有服务档位证据时使用；不复用 OpenAI 的自动倍数推导。批量、地域、工具和中转附加费用不混入普通 token 估算。
- 验证补价和手动改价后，内存报告、SQLite 查询和静态导出对同一快照得到一致费用；原始用量记录保持可追溯。
- 若来源规范化发生变化，复查索引版本和已有事件重算方式；仅添加价目时沿用既有费用重算机制。

## 验收规格

使用隔离 home 和固定 fixture，保留真实价格配置与真实日志。

- 模型：精确名、官方别名、日期快照、路由前缀、未知版本、`-free` 与精确自定义价优先级。
- 计费：普通输入、缓存读、非零缓存写、未知 TTL、已知 1 小时 TTL、推理输出不重复收费。
- 参考算例：Haiku 4.5 的普通输入 1,000、缓存读 8,000、5 分钟写入 1,000、总输出 500，标准场景费用应为 $0.00555。标准事件的总输入为 10,000、总量为 10,500。
- 上下文：新版统一标准价；旧版阈值仅使用单次请求证据；缺少政策或服务档位时保留估算说明。
- 更新：Anthropic 提供商隔离、上游字段继承、TTL 口径、来源失败、手动覆盖、旧配置兼容与容量边界。
- 三路：同一冻结数据、价目和汇率下，内存报告、SQLite 汇总与静态 HTML 一致。
- 页面：中文/英文、桌面/手机、离线、缺价、Anthropic 来源链接和 TTL 场景提示。

实现后执行相关价格、来源、服务器与三路回归，再执行项目要求的 `npm.cmd test`、`npm.cmd run typecheck`、`npm.cmd run lint`、`npm.cmd run format:check`。新浏览器模块如果引入，需同步静态导出闭包；本方案优先复用现有模块。
