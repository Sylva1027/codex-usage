# 模型娘化角色皮肤系统计划

日期：2026-10-01，更新：2026-10-02。状态：用户已完成全部角色；ChatGPT 的[独立页面预览](../validation/2026-10-02-gpt-skin-preview/README.md)已切换为用户新提供的透明线稿。最新五项要求已纳入本计划：默认透明度 50%、现有功能布局不可压缩、文/A 左侧同款衣服按钮、同级独立弹窗、浅深配色同时对比。正式系统接入及按新约束更新样张尚未开始。此前配色方案已撤下，具体颜色后续再定。逐项实施清单见 [TODOs](2026-10-01-model-character-skin-todos.md)。

## 1. 目标与范围

为 Agent Usage 增加按模型家族选择的角色皮肤：同一个娘化角色的侧视线稿位于页面左侧、正视线稿位于右侧。当前只规划用户现有角色素材的接入、布局、选择交互和离线支持，沿用页面现有外观。

用户最新要求优先：取消此前十个角色的全部颜色组合、具体色值、幻彩效果和颜色分组，不把最初示例或自行补充的配色作为当前设计依据。页面底色与全部元素联动换肤保留为后续目标，配色阶段暂缓，后续重新调整；当前不为任何角色指定颜色。

外观必须为功能服务。除本次明确增加的皮肤按钮与独立弹窗外，现有框体尺寸、内容宽度、间距、列数及排布方式保持原有规则，不能因展示角色而压缩或重排。宁可让角色被框体大面积遮住，也不为角色挪出空间。最新要求替代此前预留侧栏、缩窄中央看板和改变工具栏排列的设想。

以模型家族作为皮肤单位，同一家族的不同版本共用角色。本轮明确目标为十套角色：ChatGPT、Claude、GLM、Gemini、DeepSeek、Kimi、Qwen、Grok、Muse、Mimo，全部纳入接入范围。

用户已说明所有角色均已完成。角色外观、造型和身份以用户现有素材为准，删除此前自行拟定的造型、人设及角色制作任务。工程上仍需核对素材文件与角色的对应关系、正侧视资源、格式和显示参数；这些检查不代表角色需要重新设计。

当前已交付计划、清单，以及使用 ChatGPT 原图的独立布局预览。新透明线稿已核对尺寸与透明度，并原样复制到预览资产目录，以 alpha 遮罩按现有正文色显示线条，原图版本留作对照。2026-10-02 保存点检查发现项目 `lineart assets/` 中十套角色共二十张正／侧线稿已齐，均为可读 RGBA PNG；其余角色的实际视角、透明通道内容及显示参数仍待逐套核验，正式运行时代码未接入。用户完成角色、素材文件到齐、独立预览和正式系统交付分别记录。

## 2. 已核实的项目基础

- 前端为原生 HTML、JavaScript ESM 和 CSS，入口为 `public/index.html`、`public/app.js` 与 `public/styles.css`。
- `public/app-state.js` 保存页面状态；现有 `state.theme` 和根节点 `data-theme` 只区分 light／dark。
- `codexUsageTheme` 已持久化明暗偏好，HTML 首屏脚本在样式加载前恢复该偏好；`setTheme()` 会触发页面重绘。
- 页面已有陶瓷面板、槽底、高光、边缘、凹凸阴影等变量。CSS 后半段多次覆写材质，不能只改开头的 `--bg`、`--panel`。
- `public/app.js` 中的 `CATEGORY_PALETTES`、`categoryColor()`、`getModelColor()` 等另行生成图表色；部分控件和阴影仍使用固定颜色。
- `.shell` 当前宽度为 `min(1440px, calc(100vw - 32px))`。保持这一宽度及现有响应式排布，普通桌面空白不足时允许框体遮挡双侧立绘。
- 文/A 按钮为 `#languageToggle`，沿用 `.theme-toggle`；最终桌面样式宽 64px、最小高 38px、圆角 13px，≤720px 时与同组按钮一起变为 60px 宽。新入口直接复用其共同样式，随现有断点变化。
- “数据来源”与“更新计价标准”分别使用独立的 `.dialog-backdrop` 和 `.dialog`，具备遮罩、标题、内容、操作区及既有关闭／焦点行为；皮肤弹窗与它们同级。
- `src/static-export.js` 显式内联浏览器模块，要求从 `file://` 打开的单文件 HTML。角色素材和新增模块需要一起纳入离线导出。
- 本地服务器当前显式声明 SVG MIME；使用 WebP／PNG 需要补充对应 MIME。
- 皮肤系统实施前先保存现有计价、看板修正、计划、预览与素材；每次实施仍按具体文件核对工作区变更，避免覆盖其他工作。

## 3. 素材展示与构图

### 3.1 整体构图

现有看板保持原有布局；左侧角色与右侧角色作为独立背景装饰叠加，不参与看板的空间分配。页面沿用现有数据结构、陶瓷质感、左上光源和圆润凹槽；人物外观直接使用用户已完成的角色。

- 左侧：使用该角色已有侧视线稿；右侧：使用该角色已有正视线稿，正确绑定两张资源。
- 两侧：根据素材实际尺寸与留白配置缩放、显示锚点、头部高度与落脚基线，只调整人物的显示参数。
- 默认透明度为 50%（渲染层 `opacity: 0.5`），作用于两侧角色整体，与源 PNG 自带的透明通道叠加；不修改源图或框体透明度。
- 素材展示保留原有角色外观，不重新绘制造型、调整画风或指定新的角色线色与服装颜色。
- 当前纯透明线稿沿用页面现有正文色作为遮罩前景，适配已有明暗模式，不定义角色专属色板。
- 在现有明暗模式下检查素材可见性，选择适合原始素材的显示方式；角色与整页配色后续再调。
- 图层位于现有内容、框体和全部弹窗下方、环境背景上方，使用 `pointer-events: none` 和装饰性无障碍标记。允许人物延伸到框体后方并被遮住；如需抑制内容区域的线条，只处理装饰层的遮罩，不改框体材质或布局。
- 默认静态展示。皮肤切换时做短淡入淡出；尊重减少动态效果偏好。

### 3.2 现有素材使用原则

- 十个角色全部使用用户已有素材，不再安排角色设定、造型提案、绘制或生成阶段。
- 侧视与正视直接按文件映射，工程检查记录格式、尺寸、透明度、留白、视角和路径。
- 选择面板优先复用现有缩略图；没有独立缩略图时，可直接使用已有正视资源做界面预览，无需新增角色绘制。
- 布局样张只调整角色摆放、遮挡、缩放和响应式，以原有看板尺寸与排布为固定参照。

### 3.3 配色阶段：暂缓

全部角色的具体颜色待定，当前不指定色值、服装色或幻彩效果，也不修改页面现有颜色。现阶段明确选择界面的展示规格和数据结构：每套皮肤必须支持独立的浅色与深色组合，并在同一界面直观对比。后续再重新确定十套角色与整页元素的配色，实施语义变量、图表系列色和全组件适配；不得把此前取消的配色用于填充预览。本阶段验收不冒充配色完成。

## 4. 交互与状态设计

### 4.1 选择入口

在文/A 按钮 `#languageToggle` 左侧紧邻增加一个皮肤按钮，按钮唯一可见内容为“一件衣服”的图标。按钮的尺寸、材质、圆角、边框、高光、阴影、间距及悬停／按下／焦点外观与文/A 按钮完全一致，直接复用共同按钮样式，包括手机断点；仅替换按钮内容，不添加文字标签或另造按钮风格。

衣服图标使用本地内联 SVG，沿用项目图标的线宽与当前前景色。提供中英文 `title` 与无障碍名称“选择皮肤”，以及弹窗关联状态；点击打开独立皮肤选择弹窗。新增按钮不能挤压已有按钮、缩小标题或为角色展示重排顶部及下方内容。

### 4.2 独立皮肤选择弹窗

新增独立 `#skinDialog`，与“数据来源” `#importDialog` 和“更新计价标准” `#pricingDialog` 处于同一层级，不作为它们的子弹窗、下拉菜单或侧栏。复用 `.dialog-backdrop`、`.dialog`、标题、操作区与项目既有弹窗交互，沿用陶瓷材质、光源、圆角、凹槽、边框、阴影、字重和间距。比较区域可以使用更宽的弹窗尺寸，页面背景中的看板保持原有尺寸。

- 本轮完整选项：经典，以及 ChatGPT、Claude、GLM、Gemini、DeepSeek、Kimi、Qwen、Grok、Muse、Mimo 十套角色。接入期间只展示资源映射有效的选项，不展示无法选择的空项。
- 选择后立即应用，关闭再打开时保留当前选择。
- 提供“显示角色”开关与百分比透明度设置，默认 50%，可恢复到 50%；仅作用于立绘，不改变看板或弹窗的透明度。
- 提供恢复经典外观。首次保持用户原有明暗偏好与经典皮肤，用户主动选择角色皮肤后记住选择。
- 支持中英文、Escape、关闭按钮、键盘选择、弹窗内焦点约束及关闭后返回衣服按钮，沿用同级弹窗的背景遮罩与关闭规则。角色装饰不得遮挡弹窗或获得焦点。

### 4.3 皮肤名称与浅深配色对比

采用统一尺寸的皮肤卡片矩阵，一眼能比较多套皮肤。每张卡片同时包含：皮肤名称、可选角色缩略图、标明“浅色／深色”的两组配色，以及当前选择标记。每套皮肤的浅色与深色预览并排常驻，不跟随主页面明暗模式隐藏其中一套。

- 配色以有明确含义的色块展示页面底色、框体色、正文色与强调色等组合；同时给出浅深各一张相同内容的微型界面预览，直接展示这些颜色在面板、文字、按钮与图表中的关系。色块和预览使用真实皮肤配置，不凭空补色。
- 所有卡片使用相同的界面模板、样例内容、缩放、色块顺序及 50% 角色透明度，保证比较的是皮肤效果。名称和浅深标签常显，选中状态另用边框／标记表达，不仅依赖色差。
- 桌面使用宽弹窗和紧凑多列矩阵，优先让本轮十套角色及经典选项的名称、浅深色组在首屏总览；例如 1920／1440px 下先验证五列两行角色卡片，经典作为同屏紧凑选项，再按可读性确定尺寸。不能用单列长列表、轮播、悬停才出现的配色或逐个点击后才生成的预览作为主要选择方式。
- 不要求先切换整个页面才能查看颜色，不设置只展示浅色或只展示深色的全局预览开关。用户直接比较卡片后选择皮肤，主页面按自身当前明暗模式应用对应一套。
- 小屏采用适配弹窗可用空间的紧凑总览，先保留全部皮肤名称及两组色块，必要时缩减角色缩略图与微型界面细节；同套浅深组合始终一起显示，不把双套比较改成反复点选。受屏幕物理空间限制的细节查看也不能取代同屏配色总览。
- 具体配色仍待确定。准备阶段可以完成弹窗结构、名称和资源映射，并明确显示“配色待定”；最终配色比较验收必须等真实浅深配置具备后完成。

### 4.4 皮肤与明暗模式

当前皮肤负责角色身份与对应资产，明暗模式继续控制现有页面亮度。拟采用根节点 `data-skin="chatgpt"` 与 `data-theme="dark"` 两个维度；角色专属颜色后续再接入。

现有 `codexUsageTheme` 继续保存 light／dark；新增版本化偏好键保存 skinId、角色显示与数值透明度，透明度缺省为 0.5，非法值回退到默认。新增皮肤状态不复用模型筛选、来源或计价状态，用户浏览某个模型不会自动改变皮肤。皮肤注册表预留同一皮肤下 `light`／`dark` 两套配置，比较卡片和最终页面共用真实配置。

启动时在绘制前恢复并验证偏好；未知／已移除皮肤回退经典，存储不可用时仍能切换。当前切换只更新角色资产、装饰参数和必要的重绘，后续配色配置具备时再应用对应明暗色组；保持原有看板布局、当前范围、搜索、排序、输入草稿与刷新状态。连续切换时只应用最后一次选择，避免图片异步加载后错配。

## 5. 布局与响应式

采用不占布局空间的独立装饰层，角色固定在视窗两侧，下方适当裁切；页面滚动时保留角色构图，不给长页面铺满重复人物。人物可以延伸到现有框体下方，由框体自然遮挡，不建立会挤压内容的三列布局或预留侧栏。

- 所有屏幕档位保留经典外观的 `.shell` 宽度、工具栏行列、卡片网格、表格、图表、控件尺寸、间距及原有断点。不得为了立绘改变这些规则。
- 大屏利用框体之外的自然留白展示双侧角色；普通桌面允许只露出部分人物，不要求露出全身、脸部或完整轮廓。
- 空间不足时只裁切、缩放或收起装饰。手机可隐藏背景立绘，在独立选择弹窗中保留配色比较与资源缩略图。
- 默认透明度保持 50%，不以改变框体透明度或移动功能内容来提高人物可见度。
- 选择、切换、显示／隐藏角色都不改变主看板尺寸与排布。不得出现关闭角色后看板变宽、工具栏恢复一行等几何跳变。

用 1920、1680、1440、1280、1024、768、390px 检查布局；在相同视窗、语言、数据和状态下，对照经典外观与各角色皮肤的框体边界、列数、换行和间距。装饰层裁切不能制造横向滚动。历史独立预览中为人物缩窄内容和调整工具栏的样张仅作探索记录，不符合本次新约束，不能作为正式布局验收依据。

## 6. 现有角色素材接入

每套皮肤需要绑定左侧侧视与右侧正视资源，十套角色预期共二十个页面视图引用。实际文件数量、缩略图是否独立和素材格式在接入检查后记录；不要求新增设定参考或重画角色。当前不制作角色专属配色。

现有文件清单：`lineart assets/<角色名>-side-lineart.png` 为左侧资源，`lineart assets/<角色名>-lineart.png` 为右侧资源。角色名按文件大小写为 ChatGPT、Claude、GLM、Gemini、DeepSeek、Kimi、Qwen、Grok、Muse、Mimo。保存点已确认二十个文件匹配命名、PNG 格式可读且有 RGBA 通道；这一检查不代替画面视角、透明内容和正式加载验收。

接入检查与处理：

- 建立十个角色的资源清单，核对角色名、侧视／正视、文件路径和加载结果。
- 记录现有素材的原始尺寸、透明度与留白，不预设必须重做为某个画布尺寸。
- 根据实际文件选择 SVG、PNG 或 WebP 的加载方式；按实测体积评估显示副本的压缩需求，保留原始素材与角色外观。
- 只有实际适合遮罩的素材才使用 CSS mask，其余直接展示；不把位图包进 SVG 当作矢量线稿。
- 为不同视图设置独立的缩放、锚点与裁切参数，允许轮廓被框体遮挡，优先验证功能布局不变及层级正确。
- 复用已有缩略图或正视资源，并核对现有明暗背景下的显示效果。
- 接入后记录全部角色资源体积及离线内嵌增加量；不以未经检查的素材体积估算作为完成条件。

在线页面优先加载当前皮肤的两张图，其他皮肤按需预加载。加载失败时隐藏失效装饰，避免破图；缓存图片及遮罩资源，避免切换重复下载。

## 7. 技术实施位置

沿用现有技术栈，拟新增小型皮肤配置模块和主题样式文件：

- `public/skins.js`：皮肤注册表、可选皮肤、默认 0.5 透明度、偏好校验与角色资源元数据。保持纯配置／纯逻辑，使用命名导出；预留 `light`／`dark` 配色结构，具体色值后续再接入。
- `public/skins.css`：立绘层、遮罩、响应式与切换效果；本阶段不添加角色颜色映射。
- `public/assets/skins/<skinId>/`：统一命名的侧视、正视与缩略图资源；准备当前皮肤资源清单。
- `public/styles.css`：仅复用顶部按钮与弹窗共同样式，并添加皮肤弹窗比较矩阵所需局部样式；不为角色调整中央宽度、侧栏、框体或原有排布。颜色和材质变量的重构留待后续阶段。
- `public/index.html`：绘制前恢复皮肤偏好、不占布局空间的装饰层、文/A 左侧衣服按钮、同级独立选择弹窗，并加载新增样式。
- `public/app-state.js`、`public/app.js`：独立皮肤状态、选择交互、资源加载与必要重绘；沿用既有页面逻辑，图表配色后续再适配。
- `public/i18n.js`：皮肤弹窗、浅色／深色标签、配色待定、角色开关、百分比透明度及无障碍文案。
- `src/server.js`：实际使用 WebP／PNG 时补充 MIME，检查嵌套资源路由。
- `src/static-export.js`：把新增样式、配置和资源接入显式内联机制。

新模块需核对类型检查范围和导出闭包。角色元数据集中维护，后续添加家族时主要增加配置与资源。最终浅深比较预览与页面应用使用同一份配置，并复用本地样例模板，避免另维护一套与真实主题不一致的展示色。

## 8. 离线导出策略

本轮完整离线 HTML 保持与在线相同的十套角色皮肤选择能力，内嵌全部已接入皮肤的角色资源。阶段产物可只包含已完成接入的皮肤，全部十套接入与验收完成后才能标记本轮整体交付。导出器把资源路径替换为 data URL，CSS mask、缩略图和运行时换肤所用的资源清单使用同一份已内嵌映射。

- 明确检查 `img src`、`srcset`、CSS `url()` 与运行时资源引用，不能只通过现有外部脚本／样式检查就宣称立绘也自包含。
- 从 `file://` 打开并断网，逐个切换十套角色皮肤、明暗模式与角色开关，验证没有外部请求。
- 衣服图标、弹窗比较模板和具备后的浅深配色配置同样内联；最终离线文件支持同屏比较，不依赖在线缩略图或预览服务。
- 记录新增资源前后导出体积。家族数量扩大后再评估可选的精简导出；精简版需清楚说明包含的皮肤，并为未内嵌角色提供可用回退。
- 用本地内置资源制作导出，不增加运行时打包器或外部图片服务依赖。

## 9. 分阶段实施与交付

**P0：现有素材清点。** 核对十个角色的侧视／正视、格式、尺寸、透明度、留白与路径，建立工程资源清单和显示参数。角色完成状态依据用户说明，素材加载与入库状态依据实际检查。

**P1：现有素材布局样张。** 使用 ChatGPT 新透明线稿按最新要求更新样张：默认 50% 透明度，固定现有看板尺寸和排布，只调整角色参数。展示 1440px、1920px 和手机构图，包含图表和至少一个弹窗，并完成经典／显示／隐藏角色的框体几何对照。

**P2：角色切换基础。** 实现皮肤注册、文/A 左侧同款衣服按钮、同级独立弹窗、名称与浅深比较区域、偏好恢复、默认 50% 的角色装饰层和响应式；先贯通经典与 ChatGPT。配色待定期间明确展示待定状态，完成实际色组后再验收比较效果。交付保持原功能布局的角色版本。

**P3：十套角色素材接入。** 按统一资源清单接入全部十套现有角色，逐套设置显示参数，检查切换、按需加载和错误回退。本阶段交付全部十套角色的页面显示与切换能力。

**P4：在线／离线与布局验收。** 在现有深浅模式下检查十套角色的线稿显示、选择交互、键盘操作、存储失败、响应式与自包含导出，保留截图和检查结果。通过后同步现行看板／导出说明。

**后续扩展能力。** 皮肤注册表支持通过新增资源映射接入其他已有角色，具体角色范围由用户另行确定。

**后续配色：具体颜色暂缓、不排期。** 之后重新确定每套皮肤的浅色与深色组合，再实施材质变量、图表系列色、全部浮层与控件状态的联动适配，并填入已规划的同屏比较矩阵。最终交付需完成所有名称、真实浅深色组和微型界面的直观对比验收。此前撤下的颜色方案不作为默认值。

## 10. 验收标准

- 十套角色均正确绑定用户已有素材，左侧侧视、右侧正视，角色选择与显示资源一致，原有外观得到保留。
- 角色切换沿用现有页面配色；本阶段不以角色色板、专属明暗配色或幻彩完成为条件。
- 角色默认透明度为 50%，显示／隐藏、切换和调整透明度均只作用于装饰，不改变框体材质、大小或布局。
- 在页面现有深浅模式下线稿清晰可见，页面数据可读，必要控件边界与焦点清楚可见。
- 多系列图表保持区分；皮肤切换不改变数据、当前筛选、价格草稿、排序或自动刷新设置。
- 所列屏幕档位没有新增横向溢出，立绘始终在标题、按钮、表格、图表和浮层下方，允许被它们遮挡。与经典外观对照，既有框体尺寸、间距、行列及换行规则一致，角色开关无布局跳变。
- 衣服按钮紧邻文/A 左侧，桌面与手机均和文/A 按钮等尺寸、同材质、同交互外观；仅显示衣服图标，具备正确的中英文无障碍名称。
- 皮肤选择弹窗与数据来源、计价弹窗同级独立，视觉沿用项目美学；关闭、焦点、键盘与遮罩行为一致，不嵌套在其他设置窗口。
- 最终配色阶段：皮肤名称与浅深两套组合同时可见，1920／1440px 桌面首屏能总览本轮十套角色的配色，所有微型预览模板一致且来自实际配置；比较无需上下反复翻动或逐个切换页面。小屏保留全套名称和双组色块总览，双组不折叠为单套显示。
- 偏好恢复没有明显经典主题闪现；非法皮肤、存储失败、图片加载失败和快速切换有稳定回退。
- 在线只按需加载资源；离线单文件可切换全部十套角色皮肤，断网没有外部资源请求；记录完整十套资产的导出体积。
- 新逻辑有针对性回归；按代码影响运行 `npm.cmd test`、`npm.cmd run typecheck`、`npm.cmd run lint`、`npm.cmd run format:check`，并完成实际浏览器检查。
- 验证记录明确受测版本、数据条件、截图、资源体积及未测范围，之后才把对应 TODO 标为完成。
