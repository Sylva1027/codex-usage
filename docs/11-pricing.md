# 计价与自动更新

更新：2026-10-26。包含模型归并、当前官方价回算、覆盖与刷新状态、独立汇率和后台检查；本批验证见[执行记录](validation/2026-10-26-pricing/README.md)。后端已合入；本批界面接点仍在隔离副本，等待共享 UI 文件窗口，尚未在根目录激活。既有 GPT-6.1 Sol、auto-review 与 Claude 规则继续生效；历史调查见[归档](archive/2026-10-01/00-index.md)。

## 估算范围

费用是按 Token 明细和有效价目计算的 API 等价估算，不是服务商账单或订阅扣费。按总输入、缓存命中、缓存写入与总输出计价；推理已包含在总输出中，不再单独重复收取。

支持价目声明的 short/long 与 Fast/priority 档位；服务档位未知时保留 Standard 场景标记。上下文未知、缓存写入未知、明细不一致和模型缺价各有不确定性标记。无法可靠计价的部分保留为 unpriced，不能用一个总金额掩盖这些条件。

费率与来源以有效目录、`src/pricing.js` 和上游实际条目为准。文档不复制一份需要同步更新的完整价格表；目录核对日期也不代表所有厂商在同一天逐项核验。

## 模型解析与免费规则

前后端共用 `public/pricing-models.js`。`codex-auto-review`（忽略大小写与首尾空白）先按官方政策匹配为免费，旧的同名缓存或手动费率不再参与计价。其余模型解析顺序是：

1. 去除首尾空白并统一匹配大小写，空名称/Unknown model 保持未知。
2. 价目精确键。
3. 显式别名，且目标价目键确实存在。
4. 未收录的 `-free` 后缀规则。
5. 带 `-` 边界的最长已知前缀。
6. 未匹配。

解析前先用同一份有效目录计算展示身份：已确认的 DeepSeek 改名、`-sg` 与本机 `group/deepseek` 约定归入 `deepseek-flash`；`group/deepseek` 是用户自定的 Magpie 组，修改组指向后须同步别名。带 `/` 的名称仅在剩余部分能解析到价目键时去前缀；未知尾部继续保留原名。已知模型的普通版本后缀可借价，但不因此把所有版本显示成同名。

Claude 的显式映射只接受已核实的日期快照；未知 Claude 版本在免费规则之后保持 missing，不执行最长前缀借价。Bedrock 的点号 ID、Vertex 的 `@` ID 不自动改写成第一方模型。

模型表、期间比较、时间图及近期价目列表使用同一规范身份，同一模型的前缀/已知别名按当前官方目录计价，不按代理卖家另建线路价。原始日志、events.model 和 rollup 写入保留原名；规范化仅发生在读取投影。历史实时读沿用当前目录重算，已冻结 snapshot 与只读导入继续使用其固定目录；请求跨异步读取也保持同一份价目。

`-free` 推算匹配的四类费率为 0，不进入最低费率估算汇总；明确存在的同名价目条目仍优先。不能用 OpenCode 的原始 `cost: 0` 判断免费。免费推算、价目覆盖和上游实际免费政策是不同概念。

2026-10-08 核实的[官方说明](https://help.openai.com/en/articles/11369540-using-codex-with-your-chatgpt-plan)：ChatGPT 账号的 auto-review 安全检查免费，不计入套餐用量。项目以精确的 `codex-auto-review` 模型名识别这项豁免，不扩大到普通代码审查或名字相近的模型。它的输入、缓存、写入与输出费用恒为 0，明细缺失、Fast、未知上下文也不会触发最低费率或缺价提示；计价列表标为“官方免费”，覆盖率计入免费模型，自动发现不会为它补录收费价目。

普通时间范围继续统计实际审核 Token、会话、模型与性能样本。当前及上一五小时/每周限额窗口的用量、费用、时间图、明细、纪录和性能统计排除该模型，真实限额快照的百分比保持原值。历史费用沿用当前价目重算口径；这些展示规则不追溯推断过去的订阅扣费或退款，也不改写原始日志、索引事件或本地费率文件。

未知付费模型按同币种各类别的最低适用费率估算，标为 `minimum-estimate`。已知模型使用目录币种；未知模型的 ZCode/DSH 渠道前缀回退为 CNY，其余回退为 USD。这个回退是场景假设，不证明真实提供商的计价币种。

## 请求上下文与 GPT-6.1 Sol

`gpt-6.1-sol` 与 `gpt-6-sol` 是独立价目项，不通过别名借价。按本次用户提供的产品规则，Codex / ChatGPT Work 的 GPT-6.1 Sol 上下文能力显示为 500K，输入、缓存读取、缓存写入和输出在任何请求长度下都使用短上下文价，Fast / priority 使用 Fast 短档价；超过 500K 也不加收长上下文费。500K 不是加价门槛，本项目不修改客户端实际上下文配置。

规则依据标准事件的 `sourceKind`，来自原生 Codex 解析器或已有来源编号对应的类型（`main`、`jetbrains`、`extra`、`codex`）。本机已核实 Work 日志的 `originator: "codex_work_desktop"` 与 Codex Desktop 共用原生来源；不凭渠道显示名称、模型名或认证方式推定来源。外部 API、Project Log、其他工具、来源未知及其他模型保持原有规则。这是应用来源规则，不区分应用内部使用订阅认证还是 API Key。

外部来源的默认长上下文阈值仍为 272,000。实际上下文仍优先使用可信 `requestInputTokens`，没有时仅采用已经确认的 `contextLevel`，否则为 unknown；不使用跨请求累计输入猜测长上下文。Codex / Work 的长请求仍保留 long 事实，只切换计费用的价格档位；上下文未知也不再引入长短档费用不确定性，其他明细及服务档位不确定性照常保留。

该规则在共用计费入口生效，旧手动价格文件和自动更新继续提供有效短档单价；保留的长档价只供外部来源使用。来源类型纳入已有费用缓存键，不增加逐条数据库查询或日志读取，无需升级索引或批量重解析。实施与前后对比见[验收记录](validation/2026-10-12-codex-work-billing/README.md)。

历史事件保留原始 Token 与记录时价格版本，展示费用按活动价目重算。修改价格会影响历史费用显示，不改写原始用量日志。

## Claude 价目与场景边界

内置目录增加 17 个 Claude 版本，包含 Opus 4/4.1/4.5/4.6/4.7/4.8/5/5.5、Sonnet 4/4.5/4.6/5/5.5、Haiku 3.5/4.5、Fable 5/5.1。退役条目用于已存在记录的当前价目等价估算；没有追溯完整历史生效价格，也没有覆盖所有更早版本。第一方标准价以 [Anthropic 定价](https://platform.claude.com/docs/en/about-claude/pricing)为人工依据，模型身份以[官方 ID 说明](https://platform.claude.com/docs/en/about-claude/models/model-ids-and-versions)为依据。

单一 `cacheWrite` 费率采用 5 分钟写入场景，元数据 `cacheWriteTtl: "5m"` 随有效目录保留。非零写入缺少 TTL 时，费用说明、时间图提示和价格编辑器会说明这个假设。估算器遇到明确的 1 小时或其他不支持 TTL 时，写入部分保留为 unpriced，其余已知类别正常计费。当前来源适配器没有提供已核实的 TTL 字段；本批没有扩展混合 TTL 的事件存储和编辑界面，不能宣称支持精确的 1 小时缓存账单。

缓存读单价逐模型存储，不统一套基础输入价的 10%。Fast 仅为当前核实的 Opus 5.5、5、4.8 配置；其他 Claude（包括未知版本）带 Fast 标记时保留 Standard 场景及提示。4.6 及以后已收录模型的 Standard 上下文不引入额外长档费率；更旧条目在单次输入超过已核验的 200K 范围时提示历史上下文政策未建模，金额仍是基础价场景。地域、批量、工具费和中转加价不纳入普通 token 估算。

OpenCode 沿用总输入重构；DSH 已依据安装包源码把非零写入并入总输入，并通过索引 v11 重新解析历史 DSH 文件。ZCode 保持当前映射，其缓存字段与输入的包含关系缺少上游写库证据；缺失或冲突明细继续使用已有估算保护。来源语义见 [DSH](data-sources/dsh.md)和 [ZCode](data-sources/zcode.md)。

## 有效价目与本地文件

内置值 → 自动来源与缓存 → 手动字段覆盖，优先级逐层提高；`codex-auto-review` 的官方免费规则独立生效，优先于同名费率。

- `~/.codex-usage/pricing-auto.json`：自动价目、来源/档位元数据、刷新与发现状态。
- `~/.codex-usage/pricing.json`：手动模型字段、手动新增条目与汇率覆盖。
- SQLite 索引保存用量；自动更新不要求清空索引。

已有旧全量配置和字段覆盖格式有兼容加载逻辑。自动来源只覆盖有可靠证据的字段，缺失字段沿用当前有效值并标记 mixed/inherited。远端明确 0、缺字段、负值、非有限数和来源冲突分别处理；手动字段始终优先。

## 自动来源与刷新

当前公开来源解析入口在 `src/pricing-auto.js`：

- Models.dev：按已识别提供商与精确目录模型键更新可映射的 USD 条目，包括 Anthropic；明确的 Claude 快照映射仍限定在 `anthropic` 提供商内。
- LiteLLM：OpenAI 的备用来源，在适配边界转换 per-token 单位。
- StepFun、MiMo、Kimi、GLM：对应官方页面的 CNY 适配，校验模型键、表头、单位和可表达的档位。
- Frankfurter：USD/CNY 显示折算汇率。

服务就绪后检查是否到期，此后每次检查结束约 1 小时再查。成功刷新门槛为 24 小时，来源失败冷却 1 小时；到期后可能再等一个检查周期，并非精确到点触发。关闭服务会停止定时器并等待在途刷新，只读导入不启动调度；测试可用 `pricingRefreshSchedulerEnabled: false` 禁用。价目弹窗的全局更新可强制检查。价格与汇率独立请求，成功一侧不抹掉另一侧失败或旧报价；本次尝试、成功核验与真正改价分别记录，部分失败不会冒充全部成功。仅发现新模型时检查必要价格源，不额外请求汇率。

目标模型匹配与全局更新分开：先用已有目录/缓存重评，只在需要时请求该目标必要来源；网络失败按 1 小时冷却，能力不支持等终态不会循环重试，适配能力或目录变化后可重新评估。当前未新增缺乏完整官方费率与上下文政策的提供商适配。

上游字段不足、结构变化或冲突时保留旧有效费率并显示原因。未知阈值、复杂时段或二维计价不通过猜测降成简单费率。当前 DeepSeek 时段/节假日规则、GLM-4.7 与 GLM-4.5-Air 的复杂二维规则保留现有本地价。

Anthropic 上游写入价只有与 5 分钟口径一致时才覆盖本地字段；缺失、不支持的 TTL 或 1.25 倍关系不符时继承有效本地写入价并标注 inherited。别名与固定快照出现价格冲突时不更新该条目；上游额外上下文档位不会擅自改变 Claude 的已声明政策，未核实的 Fast 能力也不引入。

来源映射数是维护范围，不能当作本次抓取成功数。2026-09-30 的 82/86 是带日期的历史覆盖快照；现行统计分别解释“实际使用的模型有价”“由自动来源维护”“本次核验与改价”。

## 在用模型与新模型发现

在用列表从最近一个滚动日历月内出现的原始模型名构造，按规范身份合并并保留来源 harness；未匹配模型仍显示原名。时间窗口按 UTC 日历月回退，月底夹到目标月末；最后使用时间严格大于 cutoff 且不晚于基准时间才活跃，恰好一个月未出现就退出。先排除无效/未来时间，再取最后使用时间；没有新日志也会随时间退出，重新出现即回归。

列表和覆盖率共用 activeHarnessModels，明确空名单不回填历史。模型覆盖按唯一近期规范名计算，免费规则单独计数，多 harness 共享模型保留来源信息，避免重复编辑。查询费用详情另按当前查询 token 计算最低费率估算与真正 unpriced 份额，两种分母不混用。机制和来源/汇率状态由主动展开的详情承载。实时请求重新计算活跃投影，冻结请求使用 snapshot 的 asOf。退出不删除历史事件、价目、手动覆盖和自动发现记录；“全部模型”仍包含目录和历史缺价模型。

更新页面资源但未重启旧服务时，响应可能缺少近期字段。前端先尝试另一响应的近期名单，再按最后使用时间重建；若完全没有时间信息，暂显示已观测模型并提示重启后恢复近月筛选。列表和覆盖率共用这一选择，字段缺失不等于明确空名单。旧契约兼容与真实服务恢复证据见[反馈验收](validation/2026-10-01-dashboard-feedback/README.md)。

索引就绪后以全历史模型集合检查缺价发现候选，近期在用名单的退出不会削弱发现能力。当前仅自动创建有完整证据的 OpenAI USD 文本模型：提供商、必需费率、上下文与 Fast 档位必须可靠，不能由宽松前缀或其它厂商的同名价格推断。免费推算模型不进入收费发现候选。

发现使用冷却、并发合并、缓存原子写入和失败回滚。整个目录上限由共享 `MAX_PRICING_MODELS` 统一为 256 项（包括内置与扩展），PUT 价目请求体上限仍为 128 KiB；常见 256 项配置及 API 保存已通过验证，超大请求仍拒绝。`createUsageServer({ automaticDiscoveryEnabled: false })` 可禁用新模型补录；已有缓存条目仍可加载和更新，缺价提示仍保留。未知 Claude 不进入 OpenAI 自动新模型创建流程。

## 汇率与保存

汇率只用于混币图表和比较，原金额按 USD/CNY 保留。界面区分自动值、手动生效值、下载时间与来源；“恢复自动汇率”先修改草稿，保存才清除手动覆盖，取消不保存。恢复汇率不清除手动模型字段，服务器采用最新自动值或有效兜底。

保存通过版本校验避免覆盖并发编辑，冲突保留本地草稿。手动汇率即使暂与自动报价相同也保持锁定，只有明确恢复自动并保存才解除；未保存的模型/汇率草稿不会被后台状态更新覆盖。有效价目变化会使费用刷新；只改变来源或冲突状态不冒充费率变化。
