# GPT-6.1 Sol：Codex / ChatGPT Work 计费实施计划

日期：2026-10-12。状态：已实施。以下保留原计划与预算语境；现行规则见[计价说明](../../11-pricing.md)，前后对比及验证限制见[验收记录](../../validation/2026-10-12-codex-work-billing/README.md)。

## 目标与边界

- Codex / ChatGPT Work 中的 GPT-6.1 Sol 上下文能力信息更新为 500K。
- 上述用量无论上下文长度，输入、缓存读取、缓存写入、输出均采用对应的短上下文单价；Fast 仍采用 Fast 短上下文价。
- 500K 是能力信息，不是新的加价门槛。本项目只更新记账与展示，不修改客户端的实际上下文配置。
- 外部 API、其他工具及其他模型保留现有计费规则；来源不明确时不推定豁免。
- 沿用现有“按当前有效价目重算历史费用”的方式，本次不增加按生效日期分段的历史账单系统。

## 已核实的基础

本机日志包含 `originator: "Codex Desktop"` 和 `"codex_work_desktop"`。两者适用相同规则，计费可复用已有来源编号和类型，不依赖渠道显示名称，也不将认证方式当作应用来源。

2026-10-12 只读检查时，现有索引有 48,752 条用量、456 个文件；其中 GPT-6.1 Sol 有 3,411 条、41 个文件，全部属于 Codex 来源，按当前 272K 门槛均无需长上下文价且无上下文未知记录。短档价格保持不变时，预计这批历史金额不变；实施前需重新确认这份基线。

## 历史与性能约束

不批量改写历史 Token、上下文标记或记录时价格版本，不清空索引。存在适用长上下文记录时，历史展示金额及费用排名/纪录可以随新规则变化；其他模型和来源的金额应保持原结果。

来源对应关系在批处理前准备，事件处理中只做简单查表与判断。不增加逐条文件读取、数据库查询、全来源扫描或整份价目复制。规则更新后相关缓存需重新预热，正常刷新继续复用。
