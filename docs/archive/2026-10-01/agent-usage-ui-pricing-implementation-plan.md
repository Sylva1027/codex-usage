## 实施约定与范围

- 产品仍是现有 Node ESM + 原生 HTML/CSS/JS 应用，不为本任务引入前端框架、打包器或外部定时服务。
- 改动局限于用户 11 项需求涉及的界面、排序、价格刷新和汇率展示。保留数据源接入、限额窗口、费用计算与快照行为。
- 默认排序解释为多键比较：今日 → 本周 → 本月 → 全部，均为倒序；只在前一项相同时比较后一项。
- 仓库类型不再排在用量优先级之前；Git/非 Git 的识别和展示仍保留。
- “切断框体”解释为各功能框体独立且按内容收紧，框体之间露出环境背景。不是仅缩小原有整行框的内边距。
- 时区选择器仍是现有 local/utc 状态，迁移后同时控制日期范围解释和“上次刷新”的显示时区；不新增全球时区选择器。
- 背景压暗需要实测比较后确定，不预设深浅主题必须采用相同调整幅度，也不新增用户偏好开关。
- 手动价格与手动汇率继续优先于自动更新；增加明确状态和恢复自动汇率入口，不暗中移除覆盖。
- 本文不预填模型新价格，不承诺未经实测的覆盖率百分比。执行时核对来源，记录证据和限制。

这些是上一轮计划的具体化。执行前若发现现有代码或用户后续指示改变了相关约定，以最新代码和用户指示为准，并记录差异。

## 阶段 1：先完成独立的默认排序改动（需求 4）

目标：先交付一个不依赖视觉重排、容易验证的行为改动。

- [x] 在现有比较函数附近实现可复用的多周期比较逻辑，模型和仓库共用，不复制两份规则。
- [x] 默认状态按 `[today, week, month, all]` 依次倒序；周期值不存在时按 0；所有用量相同，再按显示名称和稳定的原始标识决胜。
- [x] 移除仓库排序中排在用量之前的 Git 类型优先分支。Git 属性仅用于身份和展示。
- [x] 保留现有表头三态切换。手动状态以选中周期和方向为主键；平手再按默认周期顺序倒序比较其他周期，跳过主键，最后名称决胜。
- [x] 恢复默认后回到四级倒序；不把默认状态误表示成四个可独立切换的升降序状态。
- [x] 给默认排序增加可访问的说明或简短 tooltip，说明优先级；手动状态继续正确更新 `aria-sort` 和排序指示。
- [x] 搜索、数据刷新、展开单元格和静态快照复用同一规则，不修改后端用量汇总或周期定义。

验收用例：今日不同；今日相同但本周不同；今日/本周相同但本月不同；前三项相同但全部不同；全部相同；今日全为 0；缺失周期；Git 与非 Git 混排；手动升降序与恢复默认。至少模型、仓库各覆盖一个多级平手场景，并保留原数组不被排序副作用修改。

已添加回归：模型与仓库均覆盖四级默认优先级、缺失周期、Git/目录混排，另覆盖手动周升序及平手后回到今日倒序。浏览器实测四级平手优先级、搜索和三态切换通过。
