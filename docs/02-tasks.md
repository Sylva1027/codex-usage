## 保留的验证与维护候选

以下来自旧计划的遗留项或当前源码核对，尚无新的实施排期。

### DSH 非零缓存写入语义：待核实

当前 `dshUsageFromRaw()` 的总输入为 `inputTokens + cacheReadTokens`，缓存写入独立记录；旧 OpenCode 评审提出 `cacheWriteTokens > 0` 时可能需要并入总输入。历史 DSH 真库样本的写入值为 0，不能证明非零情况正确。先确认上游语义，构造非零写入样本，核对总量、明细校验与计价，再决定是否修改。见 [DSH 当前边界](data-sources/dsh.md#非零缓存写入待核实)和[原决议记录](archive/2026-10-01/opencode-adaptation-plan.md#10-决议记录)。

### 来源与发现流程的浏览器专项验收：待补证据

已有 96/96 UI 检查使用合成数据，覆盖普通/Fast 费率、字段编辑、覆盖提示、汇率和离线布局；它没有证明 DSH/OpenCode 真库的全部图例、悬浮提示与来源组合，也没有直接完成旧 GPT 计划里“新模型自动补录成功后页面状态更新”的浏览器步骤。相关后端行为已有自动回归，专项 UI 仍需隔离 fixture 或明确的受测来源与构建。见[旧 GPT 验收清单](archive/2026-10-01/gpt-6.1-sol-pricing-implementation-plan.md#v3-浏览器与三路验收)与[旧 DSH 验证结论](archive/2026-10-01/dsh-adaptation-plan.md#m2-6-验证结论)。

### SQLite 迁移落点：维护候选

当前 schema 为 10，8→9 与 9→10 不改变表结构。9→10 仍将 `STORE_SCHEMA_VERSION` 用作迁移落点；未来再抬版本时需改成固定版本并增加相邻版本升级回归，避免跳过后续迁移。当前没有据此认定数据库损坏。实现入口见[增量索引](10-data-sources.md#增量索引与版本)。
