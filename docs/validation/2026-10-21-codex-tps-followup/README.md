## A：当前原始记录不能替代已审核计时

复用此前六轮、326 请求依赖的两个 rollout，有效调查读取前后 size/mtime 一致；后续归属验证使用捕获字节的临时副本，调用正式 reader/fold，结束后删除副本。没有扫描整个 home，也没有额外抽样。脱敏聚合见 [audit-result.json](audit-result.json)。

- 两文件共 1,194 条 `token_usage_record`，其 payload 顶层均未出现 start/duration/latency 字段；请求身份字段为 `response_id`。
- 文件中有 task/item 起止字段，但没有观察到可证明对应单次完整请求的起点。task_started 只有 14 + 12 条，不能给 489 + 705 个请求逐一计时。
- 对照 [codex-jsonl.js](../../../src/perf-sources/codex-jsonl.js)：usage 投影保留 response ID、请求/轮输出与时间戳；目标 item 保留 item ID 和起止；task_complete 保留轮终态字段；task_started 被忽略。把它投影出来也不能凭空建立逐请求边界。未发现可以直接恢复使用的请求时长字段。

结论限于这两份 rollout 的已检查结构，不声称所有 Codex 版本、嵌套扩展字段或其他日志均不含计时。未认证候选，故不做无依据的时长误差/P99/pooled 对比；不使用相邻 usage 差值、item span 或整轮减工具时间。未独立覆盖重试，也未扩展主/子线程矩阵。

统计范围为北京时间 2026-10-21、这两文件经正式 fold 识别且请求集合完整的已结束轮次；日期按轮内最后请求时间戳筛选，不另按 task_complete 写盘时间分组。已有计时仅指此前审核导入的 326 条，不代表网关全部计时是否存在：

- 24 轮、1,190 请求、1,117,389 输出 token；无效已结束轮为 0。
- 326 请求、233,379 输出 token 有已审核计时。
- 完整计时 6 轮；部分计时 0 轮；完全没有已导入计时 18 轮。
- 因整轮不完整而连带丢弃的已计时请求及其输出均为 0。

1,194 是两文件所有 usage 行数，1,190 是上述日期/终态范围内去重后的请求数，二者不能混用。当前范围的瓶颈是缺少已审核计时，并非整轮规则连带损失；没有证据支持本轮改请求级 n/分位口径。保留现有导入能力，后续先确认新请求的计时采集来源；只有捕获到带请求身份的完整起止，才重开 C。

## B：确认整 home 阻断，不能凭旧归属绕过

[audit.mjs](audit.mjs) 使用现有集成 fixture 和独立临时 SQLite：H 已发布 25 个样本，另一线程 L 已有独立请求及计时。在 store 完成 L 文件替换、发布前复核之前确定性追加；内存路径则在 L 的 timing lookup 内同步追加。两种追加分别执行，结果见 [isolation-result.json](isolation-result.json)。

1. 普通 `world_state` 追加：触发 `LIVE_SOURCE_CHANGED`，H 暂时从公开汇总消失；H 的 25 条持久化候选逐行未变，没有取得 partial 发布许可。
2. 相同位置追加声称属于 H 的第二个 session header：同样阻断；下一次正常同步识别为 `UNKEYABLE_RECORD`。只沿用 L 的旧归属会漏掉新的身份冲突。
3. 两种场景的内存路径都隐藏 H 并报告 `LIVE_SOURCE_CHANGED`。恢复 L 的有效内容后，store 正常同步恢复 H 的 25 个样本；排除该 home 后 H 仍立即消失。

现有依赖图证明的是读取时版本的归属。发布前发现内容变化后，它不能证明新字节没有引入另一线程、重复响应或新的依赖关系；size/mtime/首尾指纹也不是新的内容归属证明。因此当前无法安全区分上述两种变化，不增加放行分支。

若以后要实现隔离，最小必要证据是：固定文件集合；对变化文件取得稳定、完整的当前投影并重做身份与全局重复/冲突检查；证明 H 的完整依赖未变且新投影不影响 H。若又变化则停止本轮，不循环重读。这需要重新设计发布窗口，不能作为本次一行 filter 调整交付。新增/删除文件、身份转移、多 rollout 及跨线程重复仍沿用现有规则，本轮没有放宽。

本提交只保存调查记录，不包含所依赖的 TPS v2 实现。`--check-isolation` 依赖调查时工作区中的 request timing 接口、store 和集成 fixture 改动；这些实现须在后续功能提交中纳入，不能假定仅检出本调查提交即可复跑隔离场景。`--run` 还依赖本机未入库的此前审核产物及私有恢复目录，其他机器不能直接复跑。两个 JSON 是此次执行结果，不是独立构建认证。

本轮命令（仓库根目录）：

```powershell
node docs/validation/2026-10-21-codex-tps-followup/audit.mjs
node docs/validation/2026-10-21-codex-tps-followup/audit.mjs --check-isolation
node --check docs/validation/2026-10-21-codex-tps-followup/audit.mjs
```

三者通过。脚本自检覆盖部分计时连带损失、重复请求幂等及输出冲突。`--run` 为 A 的有界只读调查入口，需要此前审核恢复目录中的私有计时及只读旧库；它会覆盖聚合结果，来源变化时可能跳过并因 326 条覆盖断言失败，不应自动循环重跑。公开产物不含真实 response ID、正文或凭据。

未改产品、UI、正式测试或真实数据库，未重启服务；未重跑全仓、API/DOM、重开库及缓存重建矩阵，也不借用历史门禁宣称本轮功能完成。此次无运行时修改，验证集中于调查脚本和确定性反例。用户其他并行改动保持原样。
