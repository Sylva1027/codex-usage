# 10-21 历史事件差额证据边界

## 问题

2026-10-21 先记录到 `events=93,977`，随后记录到 `events=84,029`，差额为 `9,948`。目前要判断，这是去重、对账或计量口径变化造成的下降，还是事实行真实丢失；两者都不成立时，应明确记录为证据缺失。

## 结论：`evidence_gap`

没有找到同一口径下、分别为 `93,977` 与 `84,029` 两个时点保存的快照或 manifest，也没有两端快照的路径、哈希和逐事实对应关系。因此，当前既不能证明差额来自去重/口径变化，也不能证明发生真实丢失；更不能证明后续备份、恢复或转移补回了旧行。该证据缺口继续保留；第20项按明确证据边界交付，不表示旧差额已恢复。

## 当前可证明的事实

- 第一份草稿约在 `08:2x` 记录 `events=93,977`，当时峰值日为 `10-18`、`10,726` 行。
- 约 `09:38` 的基线记录 `events=84,029`，峰值日变为 `10-04`、`6,319` 行。
- 约 `09:00`，`source_files.indexed_at` 显示有 `291` 个 main 文件被重新索引。
- 后来的 `15:47` 恢复副本与后来的当前主库相比，`10-20` 及以前每日行数和 token 总量相等；这只能证明该副本与后来的当前库一致，不能解释更早的 `93,977 → 84,029` 变化。

## 当前不可证明的事实

- 两个原始端点各自对应的数据库路径、文件哈希、schema/应用版本、查询范围和导出时间。
- `9,948` 行的逐行或逐事实差异，及其归属的 home、来源、日期或去重键。
- 下降由去重、对账、重新索引、计量口径或实际丢失中的哪一项造成。
- 后续任何副本或备份恢复过 `08:2x` 时点的原始行，或恢复了上述差额。

可追溯边界是：只能确认上述观测时间、行数、峰值日和重索引事实；缺失的是跨越 `08:2x → 09:38` 的两个原始端点及事实桥。后续生成的副本无法反推缺失的原始端点。

## 不构成历史恢复证据

- 今日或后来时点自洽的数据库、bundle 或每日总量。
- `15:47` 副本与后来当前库在 `10-20` 及以前相等的每日行数/token 总量。
- 标有 `eventCount: 100000` 的合成基准或 benchmark manifest。
- 合成 transfer/import/restore 测试及当前实现的行为验收。

这些材料可以验证当前机制，但不能证明旧时点的 `9,948` 行是被去重还是丢失，也不能证明它们被恢复。
