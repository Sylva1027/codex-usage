# TPS 计量范围调查

2026-10-21。只读调查完成，产品修复未实施。推荐方案与实施卡见[TPS 计量口径修订与历史恢复方案](../../plans/2026-10-21-tps-measurement-correction-plan.md)。

- [audit.mjs](audit.mjs)：读取本机既有 SQLite 候选与脱敏投影，复用 Codex ownership 证明；只读账本 GET，不写上游数据、不调用索引同步、不扫描原始目录。含顺序区间及请求去重的断言自检。
- [evidence.json](evidence.json)：同一索引事务的时间/版本、各来源缓存数量、今天所有模型/强度结构核查及六轮账本匹配。该次 238 个轮次均完成单文件顺序检查；四个非自动复核组出现共 70 个零目标条目区间，39,863 token。Windows 投影键是大小写规范路径，SQL 按 lower(path) 关联依赖，避免误判为没有投影。
- [native-log-probe.json](native-log-probe.json)：一个目标 worker 最近 1,000 条原生日志的字段/类型计数；未取得可以按响应 ID 关联的完整计时证据，不代表所有原生历史都不可能含计时。

目标模型六轮的 326 个 rollout 响应 ID 与网关账本全部匹配，输出逐项一致，状态均 200，未出现重复匹配。账本 `ms` 求和为 1,742,789，候选请求吞吐为 133.9112193 tok/s；生产端起止/重试语义尚未认证，因此不宣称为解码速度或已上线修正值。

范围限制：结构筛查通过物理记录顺序观察输出与目标 item 缺口，不能用于生产关联计时；缓存有效不等于当前用户来源筛选或 publication policy 允许展示。只扩大核查当天元数据，未逐条审计全部历史或所有其他来源的真库。

运行：在项目根目录执行 `node docs/validation/2026-10-21-tps-scope-audit/audit.mjs`。脚本读取当前用户 home 的索引和本机已知网关账本；这是本机调查工具，不是产品依赖。会覆盖同目录 evidence.json，复跑结果可能随新请求增加而变化；已有证据的 capturedAt 和 indexVersion 只绑定当次读取。

执行结果：脚本断言自检及真实调查通过；未修改产品、正式测试、原始日志、配置或索引，未重启服务，也未重跑全仓门禁。
