# 剩余成本与后续范围

以下依据本轮 after 与各 20 次后台增量；正式浏览器周期的可见延迟由最终报告补齐。它们是后续建议，不在本轮继续扩写产品。

1. **先缩小 Codex 变化的规划触达范围。** 无变化轮已不再为六条保留缺源重新规划，前缀读取为零。但一个新线程中的普通追加仍使 home 的 metadataChanged 为真，每轮约 1,389 次前缀取证、2.803 GB，后台 p95 6.89 s。下一步应先验证哪些未变化线程/文件的已发布证据可以在本轮安全复用，保留同线程多文件合并、所有权修订、旧前缀改写、缺源与回归的反例；没有这些证据前不改成只信 size/mtime，不直接引入 Merkle 或分块格式。
2. **减少无变化轮的重复首尾探测。** 当前静止同步仍约 2.6 s；隔离探针观测到约 665 MB 的其它同步读取，主要函数阶段须进一步归因，不能把这个字节数全部叫作“前缀全文存证”。优先检查同一成功轮内相同来源 stat/首尾证据的重复采集能否复用，同时保留发布前稳定窗口和外部提交复核。ledger-only 后台 p95 3.35 s，也承担这轮原生校验。候选只做同轮复用，不增设通用长期缓存或放宽更新检测。
3. **按实际查询残余处理本月与刷新后的 miss。** 固定 now、相同修订/范围的 all perf 已接入现有静态投影，暖查询 p95 685→70 ms。今天 481→504 ms、本月 1,545→1,679 ms，没有改善；不将其描述为本轮回归已证明，A/B 顺序与机器负载未做随机化。默认刷新后的新修订、变化 now 或不同范围未必命中该投影。后续应先分别剖析 perf、分组与日线，不预先做整个响应的缓存或裁掉字段。
4. **读写架构排在上述证据之后。** 当前轻量 status 与完整同步/查询区分测量；新增读 worker/进程、跨标签页协调和刷新周期改变继续暂缓。只有残余阻塞证明确有必要，再列具体读侧方案和内存、WAL、发布一致性成本。

保留现有多 agent 规则：共享 store 整文件单写、其余文件按调用链拆卡，独立反例可并行阅读/编写；所有本地测试和真实性能测量仍共用唯一执行槽。后续卡先补最小正确性反例和短测，整合后才跑正式分布，不按 agent 数复制数据集或重复 20 分钟基准。

实际冷段封存、2×/4× 增长、长时间生产负载与故障压力没有在本轮实测。当前冻结库 0 archives，不能据本轮数字作对应性能保证。
