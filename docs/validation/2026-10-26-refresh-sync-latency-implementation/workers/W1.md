## 接入依赖

- Main 的 C-4/B-2 消费 `pendingChanges()`；即使 read 返回 false 也须检查 pending，尤其空文件 reset/消失/上次失败重试。reset 表示保守重关联，不授权删除已导入历史证据。
- `responseIds` 累积到确认，跨 clear/reset 仍可能包含当前内存已无记录的旧 ID；reset 时按完整原生关联处理，实际证据通过 `recordsForRequest()` 获取。
- 关联及性能发布成功后才 `acknowledge(snapshot.revision)`；失败/回滚不 ack，ack 返回 false 时保留新变化供下一轮处理。native projection/ownership 变化仍须独立触发关联。
- W2 的 ledger 指纹发现/确认沿用 S0：read 前取签名，完整成功后确认；无效/不匹配行也可成功确认签名。W1 不写 store、指纹或状态接线。
