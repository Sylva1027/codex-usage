## 关键断言

六例为「当前请求 / 切换范围替代 / 暂停取消」×「第二请求成功 / HTTP 500」。每例先复现 metadata 不再含可选 Codex 来源、quota → today 的纠正链。

1. 第二请求挂起时恰有两次 usage 请求，其中仅纠正请求带 `skipCheck=1`；检查 Promise 未结束，spinner 仍 busy。
2. 错误 preset 的首响应不 render，旧可见 total 保持原值；纠正载荷使用明显不同的 token 值，避免舍入掩盖变化。
3. 有效成功在真实 `render()` 返回时已显示 today 的新 total，busy 仍在；紧接着同步清 busy，只 render 一次。
4. 第二请求失败时不 render 错误载荷，显示原有错误详情、清 busy，并清空 fingerprint 以便下一周期重试。
5. 切到 month 后先释放旧纠正请求：无论旧成功或失败，都不 render、不写错误、不关闭仍待完成的新请求 busy；随后 month 正确载荷才 render 并清 busy。
6. 暂停通过真实 `setAutoRefreshEnabled(false)` 路径取消旧 load ID，并发起 `freeze=1` 请求；旧成功/失败均不能改变暂停后的状态，冻结响应可正常完成。
7. 所有完成路径的 `autoRefreshCheckInFlight` 恢复为 false；现有普通周期、失败自愈与冻结测试保持原断言。
