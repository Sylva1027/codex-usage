# TPS 展示修复验收

2026-10-30。修复生成速度表在日志追加时丢失已有数值、窄百分位区间不可见，以及样本门槛优先于 TPS 的展示排序。

## 改动

- Codex 来源读取期间发生 LIVE_SOURCE_CHANGED 时，SQLite 继续提供此前已发布的完整请求。新鲜内存扫描仍隔离尚未稳定的线程或归属变化；其他读取失败、结构错误、来源排除和无效策略继续按原规则处理。
- 模型表按未四舍五入的平均 TPS 直接降序，空值最后，同值按模型身份确定稳定顺序。样本门槛仍保留为内部统计元数据，不再影响表格顺序。
- 区间条根据 p10、p90 和均值确定局部坐标范围；相等值或单样本保留可见点。TPS、百分位、样本数和卡片尺寸不变，没有新增说明或徽标。
- 持久化汇总缓存版本升至 3，重建旧过滤和旧排序产生的缓存；用量主库 schema 不变。

## 验证

已完成的定向检查：39 项 UI 逻辑、20 项真实 Chromium 几何、89 项原生/投影回归，以及 94 项内存、SQLite、API 和缓存一致性回归，合计 242 项通过。另增加“高速少样本优先于低速多样本、缺计时最后”的排序回归，并沿用精确值排序与同值稳定性检查。

首次完整本机回归运行 3,527 项，其中 3,498 通过、25 跳过，发现四项失败：两项暴露新鲜内存读取被错误放行，已恢复原隔离规则；两项是启动器夹具错误假设用户环境为空，已改为断言父进程环境保持原值。相关 18 项复验全部通过。最终提交还须通过 Node 22 / 24 的完整 CI。

实际本机同一只读快照重放确认：旧过滤会清空已有 Codex TPS，修复后保留已完成请求。实际页面和 API 已确认恢复数值与可见区间；原始快照、截图及进程信息仅保留在本机，不纳入仓库或发布包。

## 采集与发布范围

原生计时由本机并排 Codex 引擎写入，经 reader、SQLite 与 API 展示；不依赖 Magpie，不上传用量。缺少原始生成计时的历史请求继续保留用量，不推算 TPS，也不回用请求总耗时。自定义引擎的实际采用和自然请求采集已经在本机确认；本项目源码 release 不包含该引擎的机器安装或个人配置。

保留 RANGE/SYNC 改动和并行实验目录。本轮排序上线仅重启看板后台，不重启 Desktop。后续 Desktop 重启须提前告知会话中断及手动 resume，并与用户约定时点。
