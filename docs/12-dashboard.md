## 使用场景与布局基准

本地看板读取 PC 上的用量记录，主页与各弹窗面向桌面鼠标键盘操作，以 16:9 高分辨率大屏为主要设计场景。手机使用这些页面不属于当前需求。桌面显示缩放、浏览器侧栏、并排窗口和短窗口仍会影响实际可用空间，相关适配按桌面窗口处理。

下文的窄窗口行为描述现有 CSS 在空间受限时的表现，不表示独立的手机产品定位；历史验收中的手机尺寸截图保留其原始测试语境。后续界面工作的验收基准见[开发说明](03-development.md#界面设计与验收基准)。生成的分享图片另按接收端阅读场景设计，不要求生成它的本地页面也采用手机布局。

2026-10-26 跟进：标题、筛选、两排指标、趋势卡到时间图之间的纵向间距统一为 20px；主内容分区之间保留 24px。标题右侧从左到右为语言、皮肤、主题，键盘顺序一致。主页移除用于维护核查的历史归档框及其后台加载，历史数据保留、封存与查询功能继续由原有后端和 CLI 提供，见[历史保留与转移](history-retention.md)。

## 时间范围与时区

今日、本周、本月、全部按选择的 local/UTC 解释；本周为自然周。最近范围中的上个月是完整自然月，本年从 1 月 1 日到当前时间。“上一个5h”和“上一个7d”（内部请求值为“上周”，英文 Last 7d）采用本机 Codex 记录的同类真实额度周期：起点为 reset 减去实际窗口时长，终点为原定 reset 与可信提前替换起点中的较早者。到期即可成为上一轮，无需等下一轮出现；延迟使用留下的空档不计入旧轮，两者均不解释成普通日历周期。

`5h / week` 在当前 Codex 五小时和每周限额窗口之间切换。没有可信边界或没有选中 Codex 来源时，不凭空推算对应限额能力。当前五小时图按半小时、当前每周图按连续24小时显示；上一个5h只显示有用量的半小时，跨日标签带日期，最后一段截止到该轮有限终点；上一个7d只画有用量的日历日期，日期按选择的 local/UTC 解释，即使跨年也不合并成周或月。

当前和上一限额窗口仅计 Codex 套餐候选用量：结合本机原生认证/路由诊断与原始模型名，排除明确 API、外部来源、可识别的 credits 补量阶段及 `codex-auto-review`；本机代理地址本身不作为外部证据。缺少历史认证/路由证据时，以 GPT 数字系列及少量已知历史模型兜底估算。用量、费用、时间图、模型/仓库明细、纪录、性能与趋势共用筛选，普通日期范围保留全部来源。Codex 记录的真实限额百分比不据此重算。

5h/7d 始终保留三张趋势卡：较上一5h/7d、同比流速、上一5h/7d Tokens。基准为上一完整真实同类周期，不按等长时间平移；无有效基准显示 `—`，确认零用量显示 `0`。

默认只读取本机限额记录。单机明确启用 `~/.codex-usage/codex-quota.json` 中的 `recoveryEnabled: true` 后，仅在请求的当前限额边界缺失或到期时，通过官方 Codex app-server 只读补齐账户额度；已有有效边界、已确认套餐不提供该窗口、冻结快照和导入数据均不触发查询。失败至少间隔五分钟重试，不延长过期窗口。补齐的边界历史保存在本机，并进入 SQLite 元数据与静态报告；凭据由官方客户端管理，不保存 token、邮箱或原始账户标识，也不上传本机用量。

日期控件按起止范围选择，支持反向点选、清除和 Escape。时区下拉位于刷新框内右上角，复用最近范围菜单材质；支持方向键、Home/End、Enter、Escape、Tab、外部点击和选后焦点返回。local/utc 选择持久化，上海本地显示 GMT+8；切换同时影响范围解释与上次刷新时间。长范围可自动合并为周/月时间桶，图表文字和 tooltip 标明实际覆盖区间。

加载失败时，刷新框保留开关、时区和上次检查时间，只增加“异常 · 详情”入口。点击后在原框体内切换至错误详情页，长内容在固定区域内滚动；点击返回或按 Escape 回到刷新控件。两页使用相同尺寸，单行及多行错误均不改变工具栏和范围按钮的尺寸。自动刷新开启时，加载失败的范围会在下一次 60 秒检查中重试，即使来源文件没有变化。

## 用量、费用与周期对比

输入总量、缓存命中、缓存未命中、输出和推理使用[统一口径](10-data-sources.md)。费用按[当前有效价目](11-pricing.md)展示；用量表的模型显示名称统一小写，原始标识仍用于统计和解析；模型速度区域保留原名。

时间分布的“按模型”“按花销”按每个时间槽内的用量或费用排序，柱内由下到上从大到小堆叠；悬浮详情由上到下从小到大排列，与柱子从上到下的大小顺序对应。混合币种按图表采用的汇率折算后比较，详情金额保留原币种。数值相同时按模型原始名称排序。

模型与仓库支持搜索、周期对比和适用的 New Record。全部范围没有上一周期，不显示对应纪录徽标。仓库表首先展示本地 Git 仓库，这条规则高于所有周期用量和手动升降序；普通目录在后。

仓库表在 Git/非 Git 各组内、模型表在全表内，默认依次按今日 → 本周 → 本月 → 全部降序，平手时按名称和稳定原始标识；手动表头三态切换以所选周期为组内主键，平手按其余默认周期决胜，恢复默认后重新使用四级顺序。

## 来源与模型分组

扫描目录的“编辑”提供导入和来源选择入口，顶部不再重复放置导入按钮。来源选择控制哪些目录进入统计，不改变目录类型；内部 main 的徽标显示为 codex。普通范围按产品整合渠道，限额范围保留细分，详见[渠道口径](10-data-sources.md#渠道展示与归组)。Codex、ZCode、DSH、OpenCode、Claude、WorkBuddy 的计价模型按固定 harness 顺序分组；同一价目键先到先得，避免重复编辑。一个 harness 分区为空可能是模型已被前面的分区认领，不等于没有该来源用量。

近一个滚动日历月内使用的缺价模型仍显示在在用列表，不因无法解析到价目而消失；退出与覆盖率规则见[计价](11-pricing.md#在用模型与新模型发现)。在用模型/全部模型与时间分布的渠道/模型/花销采用同一分段凹槽和选中按钮材质。免费规则、别名、继承字段和冲突状态分别说明。

## 模型速度（TPS）

2026-10-21 按 [round5](validation/2026-10-20-tps-detail-panel-samples/round5.html)接入独立区域，经用户对比确认，紧接时间分布/详情下方、位于模型/仓库周期比较之前，两行左右面板对齐；本轮验收状态及证据见[实施账本](validation/2026-10-21-model-speed-implementation/README.md)。时间图只保留渠道、模型、花销三种模式。

2026-10-23按用户反馈取消界面排名功能：左侧仅“模型、来源、平均速度”三列，无排名列、排名段落、行内样本数或排序箭头。模型保留推理强度；来源显示已知provider。同source/model/effort的不同provider分别成行。多行表直接复用下方“按模型/按仓库”的comparison-table-frame、comparison-table-scroll和comparison-table，使用相同凹槽、粘性表头、行分隔与滚动风格。当前验收见[修复账本](validation/2026-10-23-tps-remediation/README.md)。

点击或用键盘选择一行，右栏首行紧凑呈现来源与 provider，准确单位的有效样本数在同一行右对齐（当前方法使用“个请求”）；下一行显示模型名和紧邻的强度，再显示平均速度和10%–90%区间。详情不显示样本日期或日期范围。端点只标10%、90%，不画端点竖线，只保留平均值竖线。缺失字段直接省略。左右面板共用高度和内边距，窄屏上下排列。平均值为样本输出token总和除以时长总和，可能落在分位带之外；刻度保留真实位置，拥挤时只调整标签。统计与来源计时边界见[数据口径](10-data-sources.md#模型生成速度tps)。

该区沿用扫描目录编辑中的来源选择及公共时间范围、时区、刷新、冻结、语言和皮肤，不增加筛选入口。刷新保留仍存在的选择及滚动；空范围或重建时清空旧行和详情，读取退化时保留后端已发布的健康行。没有有效样本不造 0 TPS。来源覆盖诊断保留在内部，不增加常驻说明、覆盖条、徽标或额外框体。

当前 tps-v6 按平均 TPS 直接降序，缺测模型置后。有效样本来自同一套本地参考分词与匹配的接收窗口，原始用量和费用独立保留。没有可测样本的模型行保持“—”，不借旧请求耗时或估算倍率。窄分位区间及单样本仍保留可见区间条；产品不增加口径说明，安装和测量细节见[数据口径](10-data-sources.md#模型生成速度tps)。

旧按性能入口已于 2026-10-20 删除，其诊断界面和旧 G4 仅保留[历史审核包](validation/2026-10-04-perf-metrics/20261004T035100/final-audit.md)语境，不作为本轮新界面的验收结果。

## 刷新与编辑

默认每 60 秒检查新记录。暂停自动刷新后，切换范围继续使用冻结的用量快照；恢复时沿用已有并发保护与轮询状态。用量轮询和价格的 24 小时刷新不是同一个计时器。

2026-10-10（U4）：**周期仍为 60 秒**；每轮先用 `since=<指纹>` 向 `/api/status` 做**内容检查**，只有内容真的变了（或当前是限额预设）才取数，**不得以少查来源换性能**（四类计数与周期 `skipCheck` 计数改前=改后，见[最终报告](validation/2026-10-09-refresh-performance-fix/2026-10-09T0525+0800/FINAL-REPORT.md)）。另修复一处"**首轮取数失败后永久停摆**"：失败的周期不再让后续周期永久跳过，自愈后恢复正常检查（自愈对照 0/0/0 → 1/2/3）。

价格弹窗修改草稿，只有保存才写入有效价目；取消保留原值。恢复自动汇率也遵守保存/取消约定。来源与计价弹窗保持焦点恢复和 Tab/Shift+Tab 边界；价格版本冲突由服务端返回明确错误。

## 语言、主题与材质

首次语言跟随浏览器首选，文/A 切换的选择被记住；提供中英文、浅色和深色。字体使用本机 Inter、Noto Sans SC 和系统回退，数字采用 tabular/lining；不加载外部字体。

陶瓷面板、槽底、边缘、高光与环境背景分开定义。环境背景最终为浅色 `#cfd8e1`、深色 `#20252b`；保持左上光源、标题凹字与槽内圆润分隔。输入值使用正文色，占位使用 muted 的 76% 混色；不同位置遵循相同语义。

标题以 38px/850 字重呈现同色凹刻，现有窄窗口规则为 32px；按最新追加要求，标题与右侧语言/主题区共用一个连续框体；两侧不再另设外框。标题行高为 1，采用 `text-box-trim: trim-both` 与 `text-box-edge: cap alphabetic` 裁切字体主体，再由 Flex 居中；不使用固定上移。现有窄窗口规则收紧横向间距和按钮宽度，容纳较宽的回退字体。最终主体上下留白见[标题像素验收](validation/2026-10-01-title-centering/README.md)。桌面工具栏采用三框布局：范围一列、自定义一列、自动刷新与时区一列，上下边缘对齐；刷新标题、间隔、开关和加载圈位于标题行，时间与时区位于下方凹槽；检查/更新用开关右侧预留的字高缺口圈每秒三帧旋转，不增加框体高度，失败时停圈并显示错误。关闭时只显示橙色“关”，不追加状态文字；冻结范围切换仍保持高度，见[关闭状态验收](validation/2026-10-01-refresh-off/README.md)。检查时间在槽内省略溢出，错误详情保留可滚动正文和返回入口。时区及最近范围菜单沿触发外框左右边缘展开，共用外R15/内R10、13px/700字重及按钮材质；时区按钮至少112px，弹层按实际宽度适配。详见[加载圈与菜单验收](validation/2026-10-01-refresh-dropdowns/README.md)。空间收窄时换行，更窄时纵向排列，范围按钮两行呈现。趋势卡文案为“同比流速”。布局以实际浏览器检查为依据。

## 界面风格与角色

衣服图标打开“界面风格”（英文 Waifu）。选择器提供 ChatGPT、Claude、GLM、Gemini、DeepSeek、Kimi、Qwen、Grok、Muse、Mimo 十款皮肤，桌面五列两行，凹陷框随内容高度收缩；窗口可用宽度不足时自动换行，短窗口仅内部卡片区域滚动。每张卡片同时展示浅深缩略图，选中以与 New Record 同款的泛光圆点标识；不显示选中文字或底部色板。简洁模式位于标题右侧，关闭位于底部。角色开关、0—100% 透明度和皮肤选择保存在本机浏览器；简洁模式保留角色开关及透明度设置。自定义配色功能不纳入主程序。

皮肤运行资源仅使用 `public/assets/skins/` 下的 40 张无损 WebP；PNG 原稿保留在作者仓库的 `lineart assets/`，通过 `.gitattributes` 的 `export-ignore` 排除于 GitHub Release 源码包及 `git archive`。恢复可选皮肤不增加 PNG 发布资源。

角色默认透明度为 50%；左侧使用侧视线稿，右侧使用正视线稿，人物允许被框体遮挡，不为装饰压缩或重排功能区。位置根据真实看板外边界和左右留白中点，以各图的面部锚点仅作横向平移；空间不足时保护脸部不被屏幕边缘切断，保留静态降级。具体实现与测量见[居中验收](validation/2026-10-02-skin-face-centering/README.md)。

内部注册表仍保留十套角色、浅深共 40 张公开 WebP，当前选择器只提供五款。`skin-palettes.js` 为配色单一来源，浅深独立，classic 不加载角色；资源 manifest 和首屏脚本由准备命令生成。2026-10-20 新轮十套 900/900、关键几何 120/120、20 图 dense-data 复查及 classic/五款 picker/在线冻结通过，但整体仍为 incomplete：目标机 OS 缩放/browser zoom 经用户确认未测，最终全仓工程门禁待独立登记，延期五款未开放或发布；大视口整页高度差 +16px 单列保留，不表述整页完全相同。弱对比 Agent Usage 字标经用户确认保留，不当作遗漏；旧“配色待定”或“需十卡上线”状态不适用于当前要求。旧 production CLI 绑定旧迁移来源，见 [CLI 兼容调查](validation/2026-10-03-skin-palette-redesign/20261003T185748/integration/m62-reaccept-20261020/engineering-gates/cli-compatibility.md)，不作为本轮通过门禁。

## 框体聚光

主界面实际凸起框体和按钮使用当前主题强调色响应细指针光标；通常排除凹陷槽、输入控件与禁用按钮。整个日历浮层（含导航按钮、日期和间隙）不响应光晕。详情面板是例外：进度条轨道、填充、文字区域和条目间隙共用父面板的同一光层、坐标与半径，跨进度条边界不熄灭或重新渐显；光层覆盖轨道和填充，文字保持在其上方。动态重建的比较区与详情条目沿用事件委托，隐藏、弹窗和指针能力变化时清理状态，不改变原有几何与按钮按下材质。

当前强度为 22%，reduced-motion 保留指针跟随、取消渐显；不支持 hover/fine pointer 时降级。原始实现和专项验证见[聚光验收](validation/2026-10-02-frame-spotlight/README.md)，详情连续光晕修复见[详情聚光验收](validation/2026-10-03-detail-spotlight/README.md)，最终强度及组合复核状态只在[任务清单](02-tasks.md)维护。
